# ═══════════════════════════════════════
# 第二部分：设计预热（必须先完成）
# ═══════════════════════════════════════

## 2.1 定位

| 问题 | 答案 |
|:---|:---|
| 这个内容解决什么需求？ | 传播有据可查的科学发现，填补大众认知与学术前沿之间的鸿沟 |
| 受众是谁？ | 具备基础科学素养的普通读者（高中以上），非专业科研人员 |
| 成功标准是什么？ | 读者能用自己的话复述核心发现，并能判断信息来源可靠性 |
| 失败代价是什么？ | 传播错误科学信息可能误导公众（食品安全、医疗等是高风险领域）|

## 2.2 数据来源（ingest）

| 问题 | 答案 |
|:---|:---|
| 主要数据源是什么？ | arXiv 预印本、维基百科科普条目、Nature/Science 新闻稿、科技媒体 |
| 触发条件是什么？ | 热度上升词 + 学术期刊引用激增 + 同行评审通过 |
| 哪些来源不可用？ | 营销软文、单一企业赞助的"研究"、社交媒体帖子 |
| 数据是否有 Mock 版本？ | 是（arXiv 摘要、维基百科 API）|

## 2.3 结构设计（structure）

| 问题 | 答案 |
|:---|:---|
| 标准结构是什么？ | 发现背景 → 核心原理（通俗解释）→ 关键证据 → 研究局限 → 现实意义 |
| 知识节点有哪些？ | 科学发现本身、实验方法、样本规模、统计显著性、与其他研究的关系 |
| 结构是否有标准模板？ | 是（见 §4.3 阶段配置）|

## 2.4 语气与风格（render）

| 问题 | 答案 |
|:---|:---|
| 文学性维度（1-5）| 3 — 专业但不晦涩，允许适度修辞 |
| 专业深度维度（1-5）| 4 — 需要准确使用专业术语，但需通俗解释 |
| 禁止使用的表达？ | 绝对化语言（"证明了"/"彻底颠覆"）；因果混淆（相关≠因果）；未注明不确定性的预测 |
| 参考风格？ | 果壳网、知识分子、《科学美国人》中文版 |

## 2.5 质量标准（adapt）

| 问题 | 答案 |
|:---|:---|
| 最低分阈值是多少？ | 70 分 |
| 哪些维度是"一票否决"？ | factual_accuracy（事实准确性）< 70 → FAIL |
| 评分权重如何分配？ | readability 25%, factual 35%, source 20%, depth 20% |
| 是否需要特殊评分维度？ | citation_check（引用是否来自同行评审文献）|

## 2.6 交付渠道

| 问题 | 答案 |
|:---|:---|
| 需要哪些 channel？ | markdown（必选）、web、feishu |
| 是否有特殊格式要求？ | 所有科学声明必须标注来源等级；禁止纯文字无引用 |

## 2.7 异常与灰区

| 场景 | 处理策略 |
|:---|:---|
| 涉及食品安全/医疗健康 | hold_publish（高风险，必须人工审核）|
| 涉及政治敏感科学议题 | double_verify（双重核实）|
| 原始论文尚未同行评审（仅 arXiv）| 在来源等级中标记 B-，摘要中注明"待同行评审" |
| 科学发现被后续研究推翻 | 触发修订模式，更新原文并标注"更新说明" |

# 第三部分：管线阶段配置
# ═══════════════════════════════════════

## 3.1 三维分类（用于 LLM prompt 注入）

```yaml
pipeline_dimensions:
  accuracy: 4          # 事实准确性：高（科学内容不允许事实错误）
  literary: 3          # 文学性：中（专业但不晦涩）
  professional_depth: 4 # 专业深度：高（需准确使用专业术语）
```

## 3.2 SLA 要求

```yaml
sla_hours: 2          # 科学事实应在 2 小时内完成全流程
                    # （不同于突发新闻的 15 分钟，但快于深度报告）
```

## 3.3 阶段配置

```yaml
stages:
  ingest:
    module: "platform/1_ingest/radar/radar_science_fact"
    config: "science_fact"
    # 触发关键词：研究发现、实验、论文、突破、科学家
    # 触发词排除：广告、赞助、单一来源

  structure:
    module: "platform/2_structure/article/article_science_fact"
    config: "science_fact"
    # 标准结构：背景 → 原理 → 证据 → 局限 → 意义（5段式）

  render:
    engine: "platform/3_render/engines/text/render_science_fact"
    config: "science_fact"
    # 语气：客观、审慎、有温度；禁止绝对化表达

  adapt:
    scorecard: "platform/4_adapt/scorecard/scorecard_science_fact"
    config: "science_fact"
    # 阈值：70分（factual < 70 → 一票否决）

  deliver:
    publish: "platform/5_deliver/publish/autopublish"
    config: "standard"
```

## 3.4 人类检查点

```yaml
human_checkpoints:
  M1: "skip"           # 选题自动通过（科学事实来源可控）
  M2: "skip"           # 结构已模板化，跳过
  M3: "skip"           # 内容已模板化，跳过
  M4: "threshold_70"  # 70分阈值（factual < 70 → 一票否决）
  M5: "skip"           # 交付自动通过
  M6: "skip"           # 发布自动通过
```

## 3.5 灰区规则

```yaml
gray_zone_rules:
  - trigger: "涉及食品安全/医疗健康/药物"
    action: "hold_publish"

  - trigger: "涉及政治敏感科学议题（基因编辑人类胚胎/气候变化争议等）"
    action: "double_verify"

  - trigger: "原始论文仅 arXiv 预印本，无同行评审"
    action: "flag_source_grade"
    # 在来源等级中降级，并在摘要中注明
```

## 3.6 评分权重

```yaml
scorecard_weights:
  science_fact:
    readability: 0.25   # 科学内容可读性要求更高（术语需解释）
    factual:      0.35   # 事实准确性（高风险，一票否决）
    source:       0.20   # 来源可靠性
    depth:        0.20   # 专业深度
    citation_check: 0.0  # 非 breakdown_news 维度，在 render 中控制
```

## 3.7 默认渠道

```yaml
channels: ["markdown", "web", "feishu"]
brand_voice: "neutral"  # 科学内容必须客观，不带倾向性
```

## 通用部分 vs 类型插件

| 部分 | 性质 | 说明 |
|:---|:---|:---|
| 第一部分：元信息 | 通用 | 所有类型均需填写 |
| 第二部分：设计预热 | **类型插件** | 每个类型完全不同，是核心差异化内容 |
| 第三部分：管线配置 | **类型插件** | 填写第二部分后，在此映射为技术配置 |
| 第四部分：可交付物 | 通用 | 完成后打勾确认 |

**模板演进规则：** 当 SOP 更新时，只需更新"通用部分"的章节结构；类型插件不受影响。
