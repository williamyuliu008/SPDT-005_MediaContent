│  Survey       │         │ SmartTextPlat │         │  已有例行任务   │

**三层分工：**

- **AI 瞭望台（分发）**：所有作品统一收纳→网站展示→全文检索

## 二、五大频道

### 📡 频道一：AI 芯事 — 芯片与算力日报

**频次：** 每日 09:00  
**赛道：** A（快反）+ B（深产）  
**服务内阁：** CDO-DATA-001、CDO-RESEARCH-001  
**数据来源：** Survey + CI Engine 算力专题 + Web 搜索

**内容：**
```
┌─ 芯片快讯（A 快反）          ← GPU/CoWoS/HBM 产能与价格变化 ≤200字
├─ 算力供需分析（B 深产）       ← 本周算力紧张度趋势 + 关键变量
├─ 供应链信号（A 快反）         ← TSMC/ASML/SK海力士 等关键动态速览
└─ 出口管制追踪（B 深产）       ← 美/日/荷政策变化 + 影响评估
```

**对接已有资产：**
- CI Engine 算力专题（每周一）→ 拆解为每日推送
- ModLib 外部扫描中的硬件/芯片相关发现 → 纳入信号池

**STP 压力点：** A 赛道"数字→快讯"准确性、B 赛道"时序数据→趋势分析"

## 四、与现有系统的对接

### 4.1 Survey（D:\9_infra\survey）→ 数据采集层

```
SmartTextPlatform 频道        Survey 能力复用
─────────────────────────────────────────────
AI 芯事                       market.py（芯片市场规模）
                              competitor.py（英伟达/AMD 竞品分析）
                              page_fetch.py（AnandTech/SemiAnalysis 抓取）

AI 开源雷达                   web_search.py（GitHub Trending）
                              collector（HuggingFace 热门模型）
                              对接 ModLib 外部扫描产出

AI 竞争态势                   CI Engine 10 家公司事件 JSON
                              competitor.py（深潜分析）
                              report_md.py（结构化报告→STP 输入）

AI 设计前线                   design_precedent.yaml 模板
                              web_search.py（Product Hunt/Dribbble）
```

**集成方式：** Survey 作为 Python 包被 SmartTextPlatform 频道的采集脚本调用，不改变 Survey 自身的独立服务定位。

### 4.2 已有例行任务 → 频道素材

| 已有任务 | 频次 | 对接频道 | 对接方式 |
|----------|------|----------|----------|
| CI Engine 每日简报 | 每早 9:30 | AI 竞争态势 | 简报 JSON → STP B/F 赛道加工 |
| CI Engine 竞争周报 | 每周一 | AI 瞭望台月报 | 周报 → 月报素材累积 |
| CI Engine 算力专题 | 每周一 | AI 芯事 | 专题数据 → 每日拆分推送 |
| AI 智囊团每日扫描 | 每早 9:00 | AI 竞争态势 | 信号 → 观点注入 |
| AI 智囊团每周深度 | 每周一 | AI 瞭望台月报 | 深度研判 → 月报框架更新 |
| ModLib 外部扫描日报 | 每日 00:02 | AI 开源雷达 | 扫描结果 → 频道主素材 |

**去重策略：** CI Engine 每日简报本身就是从 10 家公司的原始数据出发的分析。STP 频道不是替代 CI Engine，而是对其输出进行"二次加工"——用 B 深产赛道增加结构化分析、用 F 观点赛道注入判断力、用 E 科普赛道做通俗转化。CI Engine 是"情报"，STP 是"叙事"。

## 五、知识底座设计

### 5.1 三层知识结构

```
知识底座 (D:\92_products\SmartTextPlatform\knowledge_base)
│
├── 第一层：频道产出归档（日积月累）

│   │   ├── 0617_oss.md           ← AI 开源雷达日报
│   │   └── 0617_compete.md       ← AI 竞争态势日报
│   └── ...
│
├── 第二层：实体知识图谱（从文本中提取）
│   ├── entities/
│   │   ├── nvidia.json           ← 英伟达知识卡片
│   │   ├── openai.json           ← OpenAI 知识卡片
│   │   ├── tsmc.json             ← TSMC 知识卡片
│   │   └── ...
│   └── relations/                ← 实体间关系网络
│       ├── supply_chain.json     ← 芯片供应链关系
│       └── compete.json          ← 竞争关系矩阵
│
└── 第三层：决策知识（判断与框架）
    ├── frameworks/               ← 认知框架沉淀
    │   ├── ai_landscape_2026.md  ← AI 格局认知框架
    │   └── chip_cycle.md         ← 芯片周期框架
    ├── assumptions/              ← 核心假设追踪
    │   └── assumptions_log.json  ← 每期月报的假设验证记录
    └── decisions/                ← 基于知识的决策记录
        └── 2026-Q2-decisions.md
```

### 5.2 知识底座如何服务内阁

| 内阁 | 查询场景 | 知识底座提供 |
|------|----------|-------------|
| CEO | "过去三个月 AI 芯片行业最重要的三个变化" | 实体索引 + 时间线检索 → 3 条精炼摘要 |
| RESEARCH | "OpenAI 和 Google 在模型能力上的对比演变" | 实体卡片 + 关系矩阵 → 对比视图 |
| DESIGN | "最近出现了哪些 AI 产品的新交互模式" | 频道四归档 → 实体提取 + 设计模式标签 |
| KG | "当前 AI 生态中有哪些新实体需要入库" | 实体提取流水线 → 候选实体列表 |
| MKT | "下个月的 AI 竞争报告需要关注什么" | 假设追踪 + 趋势预测 → 关注清单 |

### 5.3 知识底座与 CDO-KG-001 的关系

知识底座的第二层（实体知识图谱）与 CDO-KG-001 的知识图谱内阁形成互补：
- **知识底座**：面向 AI 产业领域的专用知识（公司/产品/技术/人物）
- **CDO-KG-001**：面向全组织的通用知识图谱（方法论/SOP/内阁关系）

通过 CDO-KG-001 的跨域关联能力，可以将 AI 产业知识图谱与其他内阁的知识体系桥接。
