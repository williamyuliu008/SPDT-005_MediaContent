# SmartTextPlatform 文字频道体系设计方案

**发件方：** MKT内阁  
**收件方：** 交付内阁、CEO Office  
**文档类型：** 产品架构设计提案  
**日期：** 2026-06-17  
**版本：** v1.0

---

## 一、设计背景

SmartTextPlatform 已完成六赛道基础能力建设（快反A/深产B/创意C/技术D/科普E/观点F）并通过 V3 递进式管道升级。当前需要将基础能力嵌入日常业务，在服务各内阁的同时持续检验和优化文字创作质量。

**设计目标：** 让每个内阁每天都能收到 1-2 篇由 SmartTextPlatform 生成的高质量文字作品，覆盖全部六赛道能力，形成"使用→检验→优化"的闭环。

### 📡 频道一：「数据脉搏」— Daily Data Pulse

**服务内阁：** CDO-DATA-001  
**频次：** 每日 09:00  
**赛道：** A（实时快反）+ D（技术文档）

**内容结构：**
```
┌─ 今日数据管道状态（A 快反）  ← 从监控数据生成 100-200 字快讯
├─ API 变更摘要（D 技术文档）  ← 24h 内 API 变更的结构化说明
├─ 数据质量红黄绿灯（A 快反）  ← 缺失率/延迟率/异常率三灯快报
└─ 昨日数据消费 Top5（A 快反） ← 哪个内阁/系统消费了最多数据
```

**STP 能力检验点：**
- A 赛道：从结构化监控数据 → 人类可读快讯的格式化能力
- D 赛道：API 变更自动文档化能力
- 数据准确性：快讯中的数字是否与源数据一致

**质量指标：** 数据准确率 ≥ 99%（错一个数字即为 fail）

---

### 🔬 频道二：「知识前沿」— Knowledge Frontier

**服务内阁：** CDO-KG-001  
**频次：** 每日 10:00  
**赛道：** E（知识科普）+ B（深度生产）

**内容结构：**
```
┌─ 昨日新发现实体 Top3（E 科普） ← 新入库的高价值实体简介
├─ 知识关联亮点（E 科普）        ← 发现的跨域关联，用类比解释
├─ 知识缺口警报（B 深产）        ← 哪些领域知识密度不足，需补数据
└─ 本体延伸建议（B 深产）        ← 基于新增实体，建议扩展哪些本体分类
```

**STP 能力检验点：**
- E 赛道：将机器可读的知识图谱实体 → 人类友好的科普文本
- B 赛道：从结构化知识数据生成分析建议
- 术语准确性：实体名称和关系描述是否正确

**质量指标：** 实体描述准确率 ≥ 95%，关联解释可读性 ≥ 80 分

### 📊 频道三：「深研简报」— Research Brief

**服务内阁：** CDO-RESEARCH-001  
**频次：** 每日 11:00  
**赛道：** B（深度生产）+ F（观点论证）

**内容结构：**
```
┌─ 今日研究摘要（B 深产）    ← 24h 内完成的研究任务核心发现
├─ 行业信号捕捉（B 深产）    ← 从外部资讯中提取的行业变化信号
├─ 竞对动态（F 观点）       ← 竞争格局变化 + 观点判断
└─ 明日研究重点（F 观点）    ← 基于今日发现，建议明日聚焦方向
```

**STP 能力检验点：**
- B 赛道：多源信息→结构化分析的萃取能力
- F 赛道：从碎片信息中形成有判断力的观点
- 信息密度：是否提供了超越原始素材的增量价值

**质量指标：** 信息增量 ≥ 3 条/期，判断准确率（事后回溯）

### 🏗 频道四：「架构日志」— Architecture Log

**服务内阁：** CDO-DESIGN-001  
**频次：** 每周一 09:00  
**赛道：** D（技术文档）+ F（观点论证）

**STP 能力检验点：**
- D 赛道：技术决策→结构化文档的规范化程度
- F 赛道：设计争议→观点提炼的公正性
- 结构化质量：ADR 格式是否严格符合模板

**质量指标：** ADR 格式完整率 100%，设计评审观点无偏袒

### ⚡ 频道五：「算法快报」— Algo Flash

**服务内阁：** CDO-ALGO-001  
**频次：** 每日 08:30  
**赛道：** A（实时快反）+ B（深度生产）

**内容结构：**
```
┌─ 昨日实验摘要（A 快反）       ← 实验数/通过数/效果最佳Top3
├─ 策略回测速报（A 快反）       ← 关键指标：Sharpe/回撤/胜率
├─ 模型效果趋势（B 深产）       ← 7日滑动窗口的趋势分析
└─ 算力消耗日报（B 深产）       ← 各实验的算力消耗与ROI评估
```

**STP 能力检验点：**
- A 赛道：高频数字→格式化快讯（与数据脉搏相似的挑战）
- B 赛道：时序数据→趋势分析→文字化（最难的能力之一）
- 数字精准度：策略指标与回测平台数据的一致性

**质量指标：** 数字转录错误率 ≤ 0.5%，趋势判断与数据方向一致

## 五、持续优化闭环

```
频道日常产出 → MKT内阁周度抽检 → 发现质量问题
                                    ↓
                              交付内阁优化
                                    ↓
                              MKT内阁回归验收
                                    ↓
                              质量指标更新
```

**MKT内阁职责（不碰代码）：**

1. **每周抽检：** 从 8 个频道中各抽 1 篇产出，做六维度评分（相关性/完整性/结构性/风格/可读性/原创性）
2. **质量趋势跟踪：** 维护每个赛道的质量分数时间序列，识别退化信号
3. **优化需求提出：** 发现质量问题→撰写设计需求编号（REQ-xxx）→提交交付内阁
4. **回归验收：** 交付内阁修复后，重新跑回归测试，比对相似度/延迟/质量分数

## 六、实施路线图

### Phase 1：试点（本周）

- 上线 3 个高频频道：数据脉搏（日）、深研简报（日）、交付快讯（按需）
- 每天 3 篇产出，快速积累质量数据
- MKT 内阁每天抽检，建立质量基线

### Phase 2：扩展（下周）

- 上线剩余 5 个频道
- 接入真实数据源（数据脉搏的监控API、算法快报的回测平台）
- flashnews（A 赛道）接入行情 API，解决假数据阻断问题

### Phase 3：自治（两周后）

- 8 个频道全量运行
- MKT 内阁建立自动化抽检脚本
- 质量趋势仪表板（对接 PDC 进度理事会）
