## 二、技术可行性评估

### 2.1 可直接复用现有能力的需求

| 能力 | 来源 | 适用需求 |
|------|------|----------|
| 六赛道文字生成（A/B/C/D/E/F） | SmartTextPlatform V3 | SR-CH-001~005（全部频道） |
| Survey web_search / page_fetch | Survey | SR-CH-002/003/004（数据采集） |

**结论：核心生成引擎全部就绪，80%的工作是编排（orchestration）而非新建能力。**

### 2.2 需要新增的模块

| 模块 | 类型 | 复杂度 | 说明 |
|------|:----:|:------:|------|
| `channels/*/build.py` × 5 | 编排脚本 | 中 | 每个频道需独立的生成编排脚本，调用 STP + Survey |
| `channels/*/prompts.py` × 5 | Prompt 配置 | 低 | 各赛道 prompt 模板，规格书已提供内容模板 |
| `canvas/ai-lookout/build_site.py` | 站点构建 | 中 | Jinja2 渲染 Markdown → HTML |
| `canvas/ai-lookout/channels/*/index.html` | 页面模板 | 中 | 6个频道页 + 首页 + 时间线 + 搜索 + 知识 |
| `knowledge_base/extract_entities.py` | 实体提取 | 中 | 从 Markdown 中提取结构化实体卡片 |
| `channels/design/app_scanner.py` | 数据采集 | 中高 | App Store 非官方扫描 |
| `schedule.yaml` | 调度配置 | 低 | Crontab/Git Hook 触发配置 |
| `build_all.py` | 一键构建 | 低 | 主控脚本 |

### 2.3 技术风险点

| 风险 | 严重度 | 缓解措施 |
|------|:------:|----------|
| **SR-APP-001：App Store 无官方 API 扫描** | 🔴 高 | 规格书已正确识别此风险。优先级方案依赖公开榜单网站抓取，这些网站的 DOM 结构不稳定，需加入重试+降级机制。建议先做 Proof of Concept 验证数据来源可用性 |
| **SR-CH-003：ModLib 扫描输出格式未知** | 🟡 中 | 需 MKT 内阁提供 ModLib 日报的实际输出样例如 `D:\9_infra\module_lib\docs\daily_reports\*.md` |
| **SR-CH-001：CI Engine 简报 JSON 格式未知** | 🟡 中 | 需确认 `ci-engine/reports/briefs/*.json` 的 schema |
| **SR-KB-001：中文 NER 准确率** | 🟡 中 | 从中文 AI 产业文本中提取实体（公司/产品/技术），预计首版准确率约 70-80%。建议 Phase 1 手动种子 10 个核心实体，Phase 3 再做自动提取 |
| **网站样式一致性** | 🟢 低 | 深色主题 + 响应式，纯前端可控 |
| **频道间数据依赖链路长** | 🟢 低 | schedule.yaml 已定义 depends_on，逻辑清晰 |

## 七、总结

### 整体判断：技术可行，风险可控。

- **核心引擎就绪：** STP V3 + Survey 已覆盖全部文字生成和大部分数据采集需求。
- **新增工作量适中：** 13 天/人，主要是编排脚本和管道搭建，不是从零造轮子。
- **最大风险项：** SR-APP-001（App Store 非官方扫描）的数据源稳定性。已识别，建议 Phase 1 就启动 PoC。
- **6 项配合待确认：** 其中 CI Engine JSON schema 和 ModLib 日报格式为阻塞项，请优先提供。

交付内阁已做好技术准备，等待 MKT 内阁反馈后即可启动 Phase 1。
