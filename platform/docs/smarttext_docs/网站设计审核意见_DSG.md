## 一、总体评价

网站骨架可用（9 页完整、JS 渲染正常、定时构建就绪），但**密集信息型媒体**的体验远未达标。核心矛盾：当前是"仪表盘卡片"模式（每条信息一张大卡片），但 AI 瞭望台需要的是"报纸头版"模式（一眼看到今天所有重要内容的摘要）。

**评分：5/10**（功能可用，体验需重构）

---

## 二、信息架构问题

### 2.1 点击层级过深 🔴

```
当前路径:  首页 → 频道列表页 → 日期文章页（至少 2 次点击看到内容）
合理路径:  首页直接展示今日所有频道核心内容 → 点击展开看全文
```

**问题：** 首页的"今日概览"区通过 JS 动态渲染 4 张卡片，但卡片只显示标题+120 字摘要。用户看完首页其实没获得任何实质信息——必须在 5 个频道里逐个点进去才能看到今天发生了什么。这是典型的"Dashboard 思维"套用到了"News 场景"。

**要求：** 首页改为"报纸头版"——所有频道的今日核心内容直接展示在首页，不需要跳转。点击后看完整文章。

### 2.2 频道归档页无信息预览 🔴

```
当前:  频道列表页只显示日期链接
       [2026-06-17]
       [2026-06-16]
       ...

要求:  每个日期条目附带该日 Top 1 信号摘要
       [2026-06-17]  NVIDIA RTX Spark 发布，1 Petaflop AI 芯片重塑 Windows PC...
       [2026-06-16]  OpenAI 秘密提交 S-1，AI 最大 IPO 启动...
```

### 2.3 缺少跨频道聚合视图

当前每个频道孤立展示。对于"今天 AI 行业发生了什么"这个核心用户需求，应该有一个聚合视图：按时间线排列所有频道今日信号，或按公司聚合。

## 三、排版与信息密度

### 3.1 卡片模式浪费空间 🔴

```
当前布局（4 卡片网格）:

┌──────────────────┐  ┌──────────────────┐
│                  │  │                  │
│   📊 AI 竞争态势  │  │   📡 AI 芯事     │
│   标题            │  │   标题            │
│   120字摘要       │  │   120字摘要       │
│                  │  │                  │
└──────────────────┘  └──────────────────┘
┌──────────────────┐  ┌──────────────────┐
│   ...             │  │   ...             │
└──────────────────┘  └──────────────────┘

问题: 4 张卡片占满首屏，但总信息量仅 480 字摘要+4 个标题
大量内边距（20px）、卡片间距（16px）、区块间距（32px）浪费了首屏空间
```

**要求：** 首页采用"报纸头版"布局：

```
┌─────────────────────────────────────────────────────┐
│  🔭 AI 瞭望台                    2026-06-18        │
├─────────────────────────┬───────────────────────────┤
│                         │                           │
│  📊 AI 竞争态势          │  📡 AI 芯事               │
│  ─────────────────       │  ─────────────────       │
│  NVIDIA RTX Spark 发     │  TSMC CoWoS 产能提升      │
│  布 1 Petaflop AI 芯     │  15%，HBM 价格连续三      │
│  片，重塑 PC 为 Agent    │  周下跌...                │
│  平台...                 │                           │
│  OpenAI 秘密提交 S-1     │  NVIDIA 中国特供 Black-   │
│  启动 IPO...             │  well 售价 $6500...       │
│  Anthropic 发布 Mythos   │  出口管制新规影响评估     │
│  5，1M 上下文...         │                           │
│                          │                           │
│  [看完整日报 →]          │  [看完整日报 →]           │
├─────────────────────────┼───────────────────────────┤
│  🔬 AI 开源雷达           │  🏗 AI 设计前线           │
│  ─────────────────       │  ─────────────────       │
│  ...                      │  ...                      │
└─────────────────────────┴───────────────────────────┘
│  📊 本周信号热度                                        │
│  AI大模型 ▓▓▓▓▓▓▓▓  芯片 ▓▓▓▓▓▓  开源 ▓▓▓▓░░          │
└─────────────────────────────────────────────────────┘
```

每个频道区块展示 2-3 条核心信号的摘要（每条 80-120 字），用户首屏即可掌握今日全貌。

### 3.2 文章详情页无目录导航

当前文章详情页是纯 Markdown 渲染，没有侧边栏目录（Table of Contents）。对于 4000+ 字的深度日报，用户无法快速跳转到"格局变化判断"或"明日关注"等指定模块。

**要求：** 文章页右侧固定 ToC 导航（桌面端），点击跳转到对应 h2 标题。移动端改为顶部折叠式。

### 3.3 时间线页无筛选

当前时间线页按日期降序排列所有条目，但没有按频道/公司筛选的功能。随着内容积累，时间线会变成无法浏览的长列表。

**要求：** 顶部增加频道筛选标签 + 公司筛选下拉。

## 四、视觉设计问题

### 4.1 配色方案过于单调 🔴

```
当前配色:
  --bg-primary: #0a0e17   (深黑蓝)
  --bg-card: #1a2235      (深蓝灰)
  --accent: #38bdf8       (单一青色)

问题:
  1. 主体和卡片的色差仅 16%（#0a0e17 vs #1a2235），淹没在深色背景中
  2. 全网只有一种高亮色（青色），5 个频道没有视觉区分
  3. 文字层级仅依靠字号和粗细，缺少色彩辅助
  4. 表格、引用块、代码块缺乏差异化配色
```

**要求：**

| 改进项 | 说明 |
|--------|------|
| **频道专属色** | 5 个频道各分配一个主题色，导航、卡片左边框、信号标签使用该色。例：芯事=橙、竞争=蓝、开源=绿、设计=紫、月报=金 |
| **卡片对比度** | `bg-card` 提高亮度至 `#1e293b` 或增加微妙的顶部渐变，与主背景形成 ≥30% 的感知对比 |
| **文字层级色** | 一级标题 `#f1f5f9`、二级 `#e2e8f0`、正文 `#cbd5e1`、辅助 `#94a3b8`——当前的三级灰度过暗 |
| **表格斑马纹** | 当前表格无隔行变色，密集数据表难以阅读。增加 `#1e293b` 偶数行背景 |
| **信号状态色** | 利好🟢 / 中性🟡 / 利空🔴 / 待验证⚪ 四种状态色应用于信号标题前缀 |

### 4.2 排版细节

| 问题 | 改进 |
|------|------|
| 所有卡片圆角统一 8px，缺乏层次 | 卡片 12px、按钮 8px、标签 16px（圆角层级） |
| 行高统一 1.6，对于新闻类内容偏松 | 正文 `line-height: 1.7`（适合中文阅读）、摘要 `1.5`（紧凑） |
| 信号卡片摘要 120 字符截断太暴力 | 改为 2 行自然折行 + `…`（CSS `line-clamp: 2`） |
| 字重层级不够 | 标题 700、副标题 600、正文 400、辅助 400+`color` |
| 缺少印刷感 | 增加 `letter-spacing: 0.02em` 给标题、`font-feature-settings: "kern"` |

### 4.3 移动端体验

当前响应式仅做了一列布局适配，但：
- 导航栏 9 个链接在小屏幕上挤成两行，点击区域太小
- 文章详情页没有返回顶部按钮
- 时间线页的横向布局在小屏幕上错位

**要求：** 移动端导航改为汉堡菜单（☰），文章页增加返回顶部浮动按钮。

## 五、交互体验

### 5.1 缺少"今日 vs 昨日"快速对比

用户浏览今天日报时，无法快速对比昨天同一频道的头条。对于情报类媒体，"今天和昨天有什么不同"是最核心的用户需求之一。

**要求：** 频道区块标题右侧增加"昨日 →"链接，点击展开昨日头条（单条，非完整文章）。

### 5.2 搜索仅为全文字段匹配

当前 FlexSearch 做的是纯文本匹配，缺少按频道/日期/公司/信号类型的过滤。

**要求：** 搜索结果页增加筛选栏：按频道、按日期范围、按公司。

### 5.3 无"稍后阅读"或书签

核心信号经常需要回头查阅，但当前没有标记/保存功能。

**要求：** 每个信号条目增加 ⭐ 收藏按钮（localStorage 持久化），搜索/知识页增加"我的收藏"入口。

## 七、设计参考

建议参考以下"高信息密度媒体"的设计语言：

- **Bloomberg Terminal** — 极高信息密度、网格系统、色彩编码
- **The Information** — 简洁排版、重点高亮、信息层级清晰
- **Stratechery** — 单栏长文+右侧大纲、每日更新节奏
- **Hacker News** — 极致的信息密度（但牺牲美观）

AI 瞭望台的定位介于 Bloomberg 和 Stratechery 之间：比 Bloomberg 有更多叙事，比 Stratechery 有更多结构化数据。
