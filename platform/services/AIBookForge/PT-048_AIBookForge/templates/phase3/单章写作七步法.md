# 《为自己写一本书 · 单章写作七步法》v1.0

> **说明**：本SOP是第三阶段（写作执行）的核心工具。
> 每章遵循相同的七步流程，降低决策疲劳，确保质量稳定。
> 核心逻辑是牵引**LLM品味**和**作品品味**。

---

## Step 1：章节目标确认

**每次写一章之前，先回答：**

- **本章要回答的核心问题**：________________________
- **本章结束后，读者（我）应该能做什么**：________________________
- **本章与原蓝图的偏差**：有无调整？______ 调整原因：______

**输出**：一段200字以内的"章节目标声明"，保存到该章草稿文件头部。

---

## Step 2：素材准备（建议15-30分钟）

> **常见误区提示**：不要边写边找素材——这会频繁打断写作流。
> 提前准备好本章所需素材，一次启动，连续写完。

**收集本章所需素材**：

- 从素材库中检索相关参考资料（已有储备的引用或案例可直接调取）
- 如需新素材，用AI辅助检索/生成（如"请给我3个关于XX的案例"）
- 将素材分类为：**必须引用** / **可供参考** / **备选**

**AI辅助素材采集示例**：

```text
请给我3个关于[XX概念]的真实历史/商业/生活案例。
每个案例请包含：背景、关键事件、结果。
并注明每个案例的来源。
```

**输出**：本章的素材清单（含来源记录）。

---

## Step 3：AI生成初稿

**使用预定义的指令模板驱动AI**：

1. 打开对应的指令模板文件（见架构阶段的AI协作协议）
2. 填入本章的具体参数（核心概念、目标受众、字数要求等）
3. 附加"风格锚点"中的关键条目，或粘贴示例段落作为风格参照
4. 发送给AI，获取初稿

**示例指令（概念解释型）**：

```text
【角色】你是一位擅长用通俗语言解释复杂概念的[领域]作家，风格类似[XX作者/XX媒体]。

【任务】请解释"[核心概念]"，面向[受众描述]。

【约束】
① 避免使用专业术语（除非已定义），如有使用必须紧跟通俗转译
② 每个新概念出现时，必须紧跟一个"换句话说"的通俗转译
③ 段落不超过5行

【风格参照】
[粘贴风格锚点中的示例段落]

【格式】
第一部分：核心定义（一句话）
第二部分：通俗解释（带类比）
第三部分：一个完整案例
第四部分：常见误解澄清

【本章特殊参数】
核心概念：[具体概念]
字数要求：约[XXX]字
章节目标：[粘贴Step 1的章节目标声明]
```

**输出**：AI生成的初稿（按行文长度控制在合理范围，若单章内容过多可分段处理）。

---

## Step 4：人工审查与修订

> **核心原则**：AI生成的初稿永远是"半成品"。
> 人类的价值在于：删减冗余、补充遗漏、调校语气、确保逻辑链条完整。

**对AI初稿进行系统化审查，逐项检查并记录**：

| 审查维度 | 检查问题 | 结果（通过/不通过） | 修改内容 |
|:---|:---|:---|:---|
| **准确性** | 事实/数据是否正确？ | | |
| **完整性** | 是否回答了章节核心问题？ | | |
| **清晰度** | 是否有读不懂的地方？ | | |
| **关联性** | 是否与前后章节衔接？ | | |
| **风格一致性** | 是否符合风格锚点？ | | |
| **认知负荷** | 新概念密度是否过大？ | | |

**输出**：修订后的章节草稿。

---

## Step 5：逻辑压力测试

> **常见误区提示**：逻辑压力测试是学员最易跳过的步骤，
> 但恰恰是"为自己写书"时最重要的自我把关。
> 跳过这一步，你写出的将是"信息的堆砌"而非"知识的体系"。

**对修订后的草稿进行专项逻辑审查**：

- □ 本章的**核心论点**是什么？是否在开头或结尾明确陈述了？
  （若无法提炼出清晰论点，说明结构松散）
- □ 每个**断言**都有**证据**支撑吗？
  （在文中标出所有"声称但未证明"的句子，逐个补充证据或标注待核查）
- □ 从上一段到下一段，**推理链条**完整吗？
  （识别任何"A→C"而缺少"B"的跳跃）
- □ 本章的**结论**是否与章节目标一致？

**输出**：逻辑审查记录 + 补充修改。

---

## Step 6：风格统一

**将修订稿与风格锚点对照，调整以下要素**：

- □ 语气是否一致？（是否突然出现"官方口吻"或"口语化过头"的段落？）
- □ 术语使用是否统一？（同一概念是否使用了不同名称？）
- □ 段落长度是否协调？（是否有"信息墙"或"碎片化"段落？）

**AI辅助风格统一示例**：

```text
请对照以下风格锚点，将本文润色为统一风格：
[粘贴风格锚点]
[粘贴全文]
```

**输出**：风格统一后的章节稿。

---

## Step 7：事实核查

> **这是AI时代的"守门员"步骤**——AI最擅长"一本正经地胡说八道"（幻觉），
> 人类必须负责把关。

**执行以下核查动作**：

- □ **数据核查**：文中所有数字/统计数据的来源是否可查？
- □ **引用核查**：所有引述的原文是否准确？出处是否正确？
- □ **案例核查**：案例中的人物/事件是否真实存在？
  （AI常虚构案例或张冠李戴）
- □ **术语核查**：术语的定义是否与主流定义一致？
  （AI常自行"发明定义"或混淆相近概念）
- □ **来源标注**：以上所有经过核查的内容，是否已按要求完成来源记录？

**可疑标记系统**：若发现无法立即核实的陈述，在文中标记为：

```text
【待核查：YYYY-MM-DD：[具体问题]】
```

并在章节的"待办清单"中记录，确保后续补查。

**核查方法**：
- 使用搜索引擎交叉验证关键数据
- 用另一个AI模型交叉验证同一事实
- 有条件的可访问原始文献/官方数据源

**输出**：核查记录表（含所有已核实和待核实项）。

## Step 8：记录与提交检查点

### 单章完成记录表

```markdown
# 第X章完成记录

## 基本信息
- 章节标题：________________________
- 写作日期：________________________
- 本章字数：________________________
- AI使用记录：
  - 模型：________________________
  - 调用次数：________________________
  - 关键调用决策说明：________________________

## 质量自评
| 维度 | 自评（1-5） | 备注 |
|:---|:---|:---|
| 准确性 | | |
| 清晰度 | | |
| 逻辑完整性 | | |
| 风格一致性 | | |

## 本章遗留问题
- [ ] 待核查项：________________________
- [ ] 待补充项：________________________

## 对下一章的注意事项
- 下一章需要特别注意：________________________
```

### 检查点执行

- 执行**CP-3（每1-2章检查一次）**：
  - 回看风格锚点，确认未偏离
  - 检查本章新引入的概念是否已纳入概念图谱
  - 记录到流程日志

**输出**：完成记录 + 检查点状态更新。

## AI使用日志模板

每次使用AI时记录：

```markdown
## AI调用日志 #[序号]

- **调用时间**：[YYYY-MM-DD HH:MM]
- **调用目的**：[收集素材/生成初稿/润色/事实核查]
- **使用模型**：[模型名称]
- **Prompt摘要**：[100字以内的核心指令]
- **AI输出摘要**：[100字以内的AI回复摘要]
- **人工处理**：[收到AI输出后，我做了什么修改/决策]
- **人机分工说明**：[为什么这部分用AI？这部分为什么由人完成？]
- **幻觉/错误记录**：[AI是否有明显错误？我是如何发现的？]
```

> **元认知提示**：每次AI调用都是一次"LLM品味"的实践机会。
> 记录"为什么用这个模型"和"为什么不自己写"，比记录调用本身更重要。
