> 文档版本：v0.1
> 制定日期：2026-07-26

## 一、项目定位

### 1.1 核心任务

**为自己写一本AI辅助学习手册。**

在自己感兴趣但不熟悉的领域，用AI辅助从零构建一本3-5万字的学习用书。不是"用AI写书"，而是"用写书来学习"——书籍是副产品，学习者七个品味维度的系统性提升才是核心产出。

### 1.2 为什么这个任务是AI时代的原生任务

| 维度 | 上一时代 | AI时代（本项目） |
|:---|:---|:---|
| 知识获取 | 消费现成的书 | **按需定制知识载体** |
| 知识密度 | 固定（由作者决定） | **可精准适配读者认知水平** |
| 成本 | 出版/印刷/编辑 | **趋近于零（仅需AI对话）** |
| 迭代速度 | 极慢（等再版） | **极快（随时重写任何章节）** |
| 认知验证 | 无（读完了也不知道自己学会了没） | **有（写出来才是真学会了）** |

### 1.3 与PT-047（社科内容生产）的分工

| 维度 | PT-047 | PT-048 |
|:---|:---|:---|
| 核心输出 | 书稿（面向外部读者） | 人+书（面向学习者本人） |
| AI角色 | 内容生产者（替人写） | 认知脚手架（帮人学） |
| 质量标准 | 产出物质量 | 产出物质量**+学习者认知变化幅度** |
| 自动化程度 | 高（全流水线自动化） | 低（全流程人在回路） |
| 人机分工 | 人是验收者 | **人是执行者，AI是框架和反馈** |
| 训练目标 | 内容产出效率 | **七品味素养** |

### 1.4 适用对象

- 大学生：跨学科探索、建立个人知识体系
- 转岗者：用写书方式快速建立新领域认知框架
- 终身学习者：从"消费者"转变为"建构者"
- AI时代教育机构：作为"君子不器"素养教育的核心项目

## 二、七品味框架

> "在AI能代劳一切'术'的今天，人必须守住'道'——定义问题、设计流程、评判质量和识别边界的能力。"

七个品味构成一个完整的能力坐标系，每个维度都有清晰的训练方法和验收标准。

### 2.1 品味一：目标的品味（What & Why）

**核心命题**：我们到底要解决什么人的什么问题？

| 层级 | 描述 | 典型行为 |
|:---|:---|:---|
| 觉察期 | 知道要定义目标，但实践中常忽略 | 拿到任务直接开工，不问"为什么做" |
| 刻意期 | 能主动定义，但需消耗注意力 | 能区分受众，但容易"面面俱到" |
| 内化期 | 形成肌肉记忆，压力下仍稳定 | 动笔前能用一句话说清"读者读完会做什么" |
| 迁移期 | 能迁移到陌生领域快速适应 | 面对新领域，能快速推导出关键假设和验收指标 |

**在本任务中的具体体现**：
- 定义"我到底想学什么、学到什么程度才算够"
- 锚定核心命题（不是"这本书介绍XX"，而是"这本书回答什么困境"）
- 生态位定位（我的书"不同"在哪里，而非"更好"在哪里）
- 设计具体可验证的验收指标

### 2.2 品味二：过程的品味（How）

**核心命题**：如何让AI按我的意图稳定产出？

| 层级 | 描述 | 典型行为 |
|:---|:---|:---|
| 觉察期 | 一个提示词让AI全包，效果不好就换模型 | 效果差就换工具重试 |
| 刻意期 | 能拆3-5步，但检查点设置不合理 | 步骤间衔接生硬 |
| 内化期 | 流程有明确的"人判断点"和"AI自动点" | 能在早期发现方向性偏差 |
| 迁移期 | 面对新任务能快速设计可行流程 | 能预判风险点 |

**在本任务中的具体体现**：
- 概念图谱绘制（知识点依赖关系）
- 章节依赖图设计（强制线性思维）
- AI协作协议（指令模板库）
- 检查点体系（6个检查点，强制人工审核）

### 2.3 品味三：作品的品味（Quality）

**核心命题**：这篇内容经得起逻辑和时间的检验吗？

> 对应"文以载道"——不能认知"什么是好作品"，由如何交付、如何评价AI的产出？

| 层级 | 描述 | 典型行为 |
|:---|:---|:---|
| 觉察期 | 语法通顺=完工 | 只要"能读"就算完成 |
| 刻意期 | 能区分体裁文法要求 | 但不太会评估"论证严密性" |
| 内化期 | 交付前主动做三方面自检 | 逻辑链条/证据充分性/认知增量 |
| 迁移期 | 面对新体裁能快速建立质量判断标准 | 而非套用旧标准 |

**在本任务中的具体体现**：
- 逻辑压力测试（识别"A→C"缺少"B"的跳跃）
- 认知坡度设计（为自己设计"学习阶梯"）
- 体裁质量评审清单建立
- 事实核查机制（对抗AI幻觉）

### 2.4 品味四：LLM的品味（Boundaries）

**核心命题**：什么时候该让AI写，什么时候该自己写？

| 层级 | 描述 | 典型行为 |
|:---|:---|:---|
| 觉察期 | 什么任务都用最强模型，不在意成本 | 把所有问题都当"LLM能解决" |
| 刻意期 | 能区分任务类型，但决策依据偏直觉 | 标准不清晰 |
| 内化期 | 主动为每个任务做"AI适合度评估" | 明确标出"坚决不让AI碰"的环节 |
| 迁移期 | 面对新模型能快速评估其能力边界 | 并调整调用策略 |

**在本任务中的具体体现**：
- 不同章节类型使用不同模型
- 设计幻觉防御机制
- 人机分工红线标注（核心观点、价值判断必须人写）
- 成本控制实验

### 2.5 品味五：协作品味（Collaboration）

**核心命题**：如何让多智能体/人高效协作？

> 基础任务为可选延展。核心是理解协作接口设计和冲突解决机制。

### 2.6 品味六：伦理品味（Responsibility）

**核心命题**：如何对自己的产出和AI的使用负责？

- 引用来源管理（标注而非抄袭）
- AI辅助透明度声明（哪些部分由AI生成/辅助）
- 知识产权边界判定（区分"参考"与"改写"）

### 2.7 品味七：元认知品味（Reflection）

**核心命题**：我知道我不知道什么吗？

| 层级 | 描述 | 典型行为 |
|:---|:---|:---|
| 觉察期 | 不追踪自己的认知变化 | 写完了也不知道自己学会了没 |
| 刻意期 | 有意识反思，但无系统方法 | 偶尔回顾，没有记录 |
| 内化期 | 有固定复盘机制 | 每阶段有"旧我→新我"记录 |
| 迁移期 | 复盘方法可迁移 | 能用同样方法复盘任何学习任务 |

**在本任务中的具体体现**：
- 认知变化轨迹图（写书前→写书后）
- 能力缺口自测绘
- 决策归因复盘（"这次为什么这样做？"）

## 三、四阶段流水线设计

### 3.1 阶段总览

| 阶段 | 时长 | 核心交付物 | 训练品味 | 关键门禁 |
|:---|:---|:---|:---|:---|
| **第一阶段：立项定义** | ~1周 | 书籍立项书.md | 目标品味 + 元认知 | 自评≥7/10通过 |
| **第二阶段：架构设计** | ~1周 | 全书架构蓝图.md | 过程品味 + 作品品味 | 依赖图无循环 |
| **第三阶段：写作执行** | 3-6周 | 各章草稿.md + 流程日志 | LLM品味 + 作品品味 | 6个检查点 |
| **第四阶段：整合复盘** | ~1周 | 完整书籍.md + 四品味自评报告.md | 元认知品味 + 伦理品味 | 诚实自评 |

### 3.2 第一阶段：立项定义

**核心SOP：《书籍立项书》**

牵引"目标的品味"训练。学员不需要一次性回答所有问题，但必须在进入写作前完成。

**核心问题**：
1. 我想学什么？现在什么水平？为什么想学？
2. 这本书的核心命题是什么？（不是"介绍XX"，而是"回答什么困境"）
3. 我的书"不同"在哪里？（不是"更好"，而是"不同"）
4. 本书不做什么？（边界，比"做什么"更能体现品味）
5. 我的验收标准是什么？

**关键设计原则**：
- 牵引"目标品味"：所有问题都指向"定义清楚再做"，而非"赶紧开始写"
- 压低认知负荷：分段填写，不是一次性长文本
- 内置自检机制：10项自评清单让学员在进入写作前做一次质量判断
- 强制诚实：多处要求写"实际水平"而非"理想水平"（元认知品味前置）

### 3.3 第二阶段：架构设计

**核心SOP：《全书架构设计工具包》**

牵引"过程品味"（尤其是原子化拆解）和"系统思维"训练。

**六个核心工具**：
1. **概念图谱绘制**：所有核心概念及其关系（前置/子集/类比/混淆）
2. **章节依赖图**：章节间的依赖关系，强制识别循环依赖
3. **认知坡度设计表**：每章的"起点-终点-阶梯"设计
4. **素材地图**：各章节所需素材清单 + 采集计划
5. **AI协作协议**：全书AI调用策略 + 指令模板库
6. **检查点体系**：6个检查点位置和执行标准

**关键设计原则**：
- "为自己写书"和"为别人写书"的核心区别：认知坡度设计
- 你有权把自己的"卡点"写得极其细致——第3章特别难，可以写成4节
- 初期花1-2小时建立指令模板库，后期写作效率至少提升3倍

### 3.4 第三阶段：写作执行

**核心SOP：《单章写作七步法》**

牵引"LLM品味"和"作品品味"。

**七步流程**：
```
Step 2.1 章节目标确认
    ↓
Step 2.2 素材准备（15-30分钟，提前备好，不打断写作流）
    ↓
Step 2.3 AI生成初稿（使用预定义指令模板）
    ↓
Step 2.4 人工审查与修订（删除冗余、补充遗漏、调校语气）
    ↓
Step 2.5 逻辑压力测试（识别推理链条断裂）
    ↓
Step 2.6 风格统一（与风格锚点对照）
    ↓
Step 2.7 事实核查（对抗AI幻觉）
    ↓
Step 2.8 记录与提交检查点
```

**六检查点体系**：
| 检查点 | 执行时机 | 核心检查 |
|:---|:---|:---|
| CP-1 | 写作前 | 核心命题是否仍成立？ |
| CP-2 | 第二阶段末 | 依赖图无循环？ |
| CP-3 | 每1-2章后 | 风格是否偏离锚点？ |
| CP-4 | 全书50%时 | 内容是否与蓝图一致？ |
| CP-5 | 初稿完成后 | 核心问题是否得到回答？ |
| CP-6 | 终稿完成后 | 验收标准是否达成？ |

### 3.5 第四阶段：整合复盘

**核心SOP：《认知跃迁自评体系》**

牵引"元认知品味"。

**核心交付物**：
1. **全书一致性审查**：章节间跳跃、过渡内容缺口
2. **认知坡度终审**：整体是否平滑？有无断层？
3. **认知变化轨迹图**：写书前→写书后的认知状态对比
4. **四品味自评报告**：每个品味写"旧我→新我"的认知变化

**四品味自评报告模板结构**：
```
## 品味一：目标的品味
- "我原本想怎么做？"
- "实际怎么做的？差异教我什么？"
- "如果让AI独立做这个任务，它会在哪个环节失败？"

## 品味二：过程的品味
- "我在哪个环节强制插入了人工检查？为什么是那里？"

## 品味三：作品的品味
- "我的结论如果错了，最可能是因为什么？"

## 品味四：LLM的品味
- "这个分析/写作中，哪个部分我坚决不让AI碰？为什么？"
```

## 四、质量评估体系

### 4.1 双维度评估

| 维度 | 评估对象 | 核心指标 |
|:---|:---|:---|
| 书的质量 | 交付物 | 概念体系自洽性、逻辑链条完整性、认知坡度合理性、事实核查通过率 |
| 人的成长 | 学习者 | 七品味自评层级变化、认知变化描述的具体程度、AI幻觉发现率 |

### 4.2 评级标尺（每个品味）

- **觉察期**：知道有此维度，但实践中常忽略
- **刻意期**：能主动运用，但偶有失误
- **内化期**：形成肌肉记忆，压力下仍稳定
- **迁移期**：能迁移到陌生领域快速适应

### 4.3 终极评估题

完成四阶段后，学员应能回答：
> *"这次写书经历中，我真正学会了什么？AI帮我做到了什么？哪些是AI永远做不到的？"*

## 五、AI使用红线（设计约束）

> 以下环节**绝对禁止**让AI独立完成，必须由人做出决策或执行：

1. **目标定义**：核心命题由人确定（AI可辅助探索，但最终选择权在人）
2. **价值判断**：什么是"好"、什么是"更重要"（体裁/领域质量标准由人定义）
3. **核心观点**：一本书的立场和观点（不可外包给AI）
4. **验收标准**：如何算"成功"（由人定义，AI辅助测试）
5. **事实核查**：AI生成的事实必须由人独立核实（AI不得核查自己生成的内容）
6. **认知复盘**：我真正学会了什么（元认知品味的核心，不可替代）

## 六、技术架构设计

### 6.1 平台架构原则

**最小可行配置**：
- 3个核心智能体（BookMentor / QualityAuditor / MetaReflector）
- 4个阶段模板（SOP文档，可独立使用）
- 不依赖重型基础设施（Python环境 + AI对话窗口即可运行）

**核心区别于PT-047的架构决策**：
- PT-047 = 7个pipeline agent（生产流水线，人是验收者）
- PT-048 = 3个教练agent（训练辅助，人是执行者，AI是脚手架）
- PT-048不需要断点续生产能力（人工作坊，不追求全自动化）
- PT-048需要比PT-047更详细的"决策记录"机制（用于元认知复盘）

### 6.2 数据流设计

```
学员输入 → BookMentor（指导） → 阶段SOP执行 → QualityAuditor（审查）
    ↓                                               ↓
交付物（.md）← 元认知复盘 ← MetaReflector ← 四品味自评报告
```

## 七、迭代升级路径

### 7.1 第一阶段（v0.1）—— 手工SOP模式

- 提供完整的四阶段SOP模板（Markdown文档）
- 智能体仅用于答疑和反馈
- 学员手动填写所有模板
- **目标**：跑通完整闭环，积累第一批学员反馈

### 7.2 第二阶段（v0.5）—— AI辅助填写

- BookMentor智能体介入立项书填写过程（实时指导）
- QualityAuditor支持章节写作过程（结构化审查）
- **目标**：将部分人工操作自动化，但保留人在回路

### 7.3 第三阶段（v1.0）—— 智能训练伴侣

- 三个智能体完整协作，覆盖全流程
- 自动追踪学员在七品味的成长曲线
- 支持多领域切换训练
- **目标**：成为AI时代"君子不器"教育的标准化工具

---

## 八、关键设计约束

1. **不追求自动化程度**：PT-048的价值在于"人在回路"，不是"全自动化"
2. **不追求内容产量**：每本书的产出不重要，重要的是学员的认知变化
3. **不追求评分标准化**：自评报告的"诚实度"比"分数"更重要
4. **可重复训练**：同一学员可以多次执行（换领域/提难度），每次都有新收获
