- 本章用到"熵"概念 → 自动检测是否已在前章定义 → 决定是否插入回顾框

## 二、四层拆解：适配科普长篇

K12版：`课程 → 段落 → 知识点 → 帧`

科普版建议改为：

```
卷/全书
  └─ 篇章(Chapter)       ← 主题单元（如"熵与信息""Transformer注意力机制"）
       └─ 小节(Section)   ← 一次完整说理闭环
            └─ 说理单元(Discourse Unit)  ← 最小生成原子
                 ├─ 概念引入框
                 ├─ 类比/隐喻框
                 ├─ 形式化定义框
                 ├─ 推导/实验证据框

- **说理单元**才是LLM填槽 + 模板渲染的最小单位
- 小节 = 若干单元按逻辑顺序编排，受篇章标签约束

# 3、文风包如何真正从优秀科普作品中...

**问题详情：**

文风包如何真正从优秀科普作品中"提取+形式化"（逆向工程名家风格）"

---

好的，这块是体系里非常关键但也容易被做成「拍脑袋写YAML」的部分。我们把它严肃地拆成**方法论 + 操作步骤 + 校验标准**，让你能真正把「名家感觉」变成可复用的文风包资产。

---

## 一、先说清楚：文风包逆向工程是什么／不是什么

**是：**

> 从标杆科普文本中，系统提取**显式可观测的语言特征**，编码为规则/池子/权重，使生成文本在*统计风格维度*上逼近原作者叙事人格。

**不是：**

> 训练一个风格LoRA或用Few-shot让模型模仿——那是黑箱模仿，不可审计、不可跨模型迁移、不符合你们「表现力可编程」的哲学。

你们体系的文风包是**白盒约束层**，LLM只是执行器。

---

## 二、文风包的形式化维度（科普文体解构框架）

一个可用的科普文风包（`StylePack v1`）建议拆为 **5 层**：

```
StylePack
 ├─ 0. Meta           （适用体裁、受众、禁止项）
 ├─ 1. Persona         （叙述者角色：亲切向导 / 严谨工程师 / 故事讲述者）
 ├─ 2. Lexical Pool    （词汇池：连接词、开场语、类比触发词、禁词表）
 ├─ 3. Syntactic Bias  （句式偏好、段落节奏、标点习惯）
 ├─ 4. Rhetorical Ops  （修辞开关：设问密度、隐喻策略、举例模式）
 └─ 5. Layout/Pacing   （框类型偏好、数学展示方式、张力弧线默认映射）
```

下面逐层给**提取方法**。

---

## 三、样本准备（非常关键）

### 3.1 选材原则

- **纯文本**，排除对话体访谈、Q&A、序跋
- 选「正文说理段」，排除目录/习题/参考文献
- 同一作者 **3–5 万字**（约 1–2 本书核心章节），保证统计显著性
- 对比组：同期同题材**其他作者**样本（用于差分提取*个性特征*）

> 例：
>
> 目标＝费曼风格 → 正样本《物理定律的特征》译文＋费曼讲义精选；
>
> 负样本＝其他物理科普（盖尔曼、格林）→ 滤掉「科普通用特征」，留费曼独有。

## 四、逐层提取方法

### 🔹 Layer 0 · Meta（人工填）

```yaml
target_author: "Richard_Feynman (CN_trans_ZhangZongMing)"
genre: nonfiction_pop_science
audience: layperson_with_curiosity
prohibited:
  - passive_voice_excessive
  - jargon_without_inline_explanation
```

---

### 🔹 Layer 1 · Persona（定性＋语料归纳）

人工阅读归纳叙述者姿态，可用 3 轴打分（1–5）：

| 轴 | 说⁠明 | 费⁠曼⁠例 |
| --- | --- | --- |
| 亲⁠昵⁠度 Intimacy | 对⁠读⁠者⁠称⁠呼/第⁠二⁠人⁠称 | 5 |
| 权⁠威⁠度 Authority | 断⁠言 vs 探⁠讨⁠语⁠气 | 3 |
| 戏⁠剧⁠化 Drama | 讲⁠故⁠事/表⁠演⁠感 | 4 |

→ 写成 Persona Prompt（供模板注入用，不用于微调）：

```yaml
persona_desc: "一位坐在你旁边拿粉笔随手画图的物理老师，不断问'你猜为什么会这样？'"
narrator_voice: "first_person_colloquial"
engage_mode: "socratic_questioning"
```

---

### 🔹 Layer 2 · Lexical Pool（可半自动提取）

**做法：**

1. 分词 → 过滤停用词 → TF-IDF 差分（正样本 − 负样本）
2. 人工从高分词中挑「风格承载词」而非主题词

自动提取候选：

```python
# 伪码示意
style_words = top_k( tfidf(target) - tfidf(control) , k=200)
```

人工标注分类：

```yaml
lexical_pool:
  openers:               # 段落/小节开场
    - "咱们想一下——"
    - "假使你坐在……"
    - "这就有意思了："
  connectors:            # 句间逻辑连接
    - "你看"
    - "换句话说"
    - "其实呢"
  analogy_triggers:      # 类比引入标记
    - "就好比"
    - "想象一下"
    - "这有点像"
  hedge_words:           # 弱化断言（费曼少用→低频允许）
    - ["大致来说","在某种意义上看"]
  forbidden_words:       # 与原作冲突
    - "毋庸置疑"
    - "众所周知"
```

> ✅ 提取原则：**高频 ＋ 风格辨识度高 ＋ 不绑定具体知识点**

---

### 🔹 Layer 3 · Syntactic Bias（可读统计＋人工归纳）

**可量化特征（用简单脚本跑）：**

| 特⁠征 | 说⁠明 |
| --- | --- |
| 平⁠均⁠句⁠长（词⁠数） | 费⁠曼⁠偏⁠向⁠短⁠句 |
| 问⁠句⁠比⁠例 | 高（Socratic） |
| 破⁠折⁠号/省⁠略⁠号⁠频⁠率 | 高（口⁠语⁠停⁠顿） |
| 被⁠动⁠语⁠态⁠比⁠例 | 低 |
| 段⁠落⁠平⁠均⁠行⁠数 | 短⁠段⁠落⁠多 |

**写入约束而非复制分布：**

```yaml
syntax_bias:
  avg_sentence_len: short      # <18词偏好
  allow_dash_pause: true
  question_ratio: high         # >8% of sentences
  passive_voice: discourage
  paragraph_break_freq: often  # 每2–4句一段
  opening_pattern:
    - "random_from: lexical_pool.openers"
```

模板渲染时：

- 单元首句随机选 `openers`
- 长句超阈值 → 拆分建议
- 问句比例不足 → 插入 Socratic 反问槽位

---

### 🔹 Layer 4 · Rhetorical Ops（需人工标注抽样）

从样本中随机抽 100–150 个「说理单元」，人工标注：

**① 隐喻/类比策略**

```yaml
analogy_policy:
  density: high          # per_500words ≈ 1.2
  source_domain_pref:    # 费曼偏爱
    - daily_life
    - mechanical_device
    - game_rule
  analogy_position: ["after_concept_intro", "before_formal_def"]
```

**② 设问模式**

```yaml
rhetoric:
  open_with_question: true
  use_second_person: true
  rhetorical_question_for_emphasis: true
```

**③ 例证的「具象化程度」**

- 偏好：可操作思想实验 > 抽象引用 > 数据罗列

**④ 数学/公式处理（技术科普特别重要）**

```yaml
math_display:
  progressive_reveal: true    # 分步展开
  inline_explanation: required  # 每个符号须有自然语言对应
  hide_heavy_proof_by_default: true
```

---

### 🔹 Layer 5 · Layout / Pacing（与张力弧线联动）

```yaml
layout_pref:
  analogy_box_style: inset_gray
  sidebar_bio: false
  key_insight_highlight: "★ 核心洞察：…"
tension_default_map:
  curiosity_hook:     { opener: question, paragraph: short, pace: brisk }
  aha_moment:         { emphasis_mark: "★", slow_down: true, repeat_core_once: true }
  reflective_open:   { close_with_open_question: true }
```

## 一、社科通俗 / 历史作品的本质结构

优秀历史通俗作品（如《万历十五年》《人类简史》《枪炮、病菌与钢铁》）通常包含两层并行结构：

### ① 表层：叙事时间线（Story Layer）

```
事件 A → 人物反应 → 关键抉择 → 后果 B → 更大背景揭示
```

- 有**情节感**（但不是虚构）
- 有**人物动机与张力**
- 有**局部高潮与反转**

### ② 深层：分析框架（Analysis Layer）

```
现象 → 制度/结构解释 → 长周期因果 → 历史规律/反思
```

- 这是历史作品的「干货」
- 也是你们体系可以**模板化、参数化**的核心部分

👉 本体系的任务：

**让叙事层受控、让分析层结构化，用文风包统一二者语气。**

---

## 二、四层拆解：适配历史通俗作品

K12：`课程 → 段落 → 知识点 → 帧`

科普：`全书 → 篇章 → 小节 → 说理单元`

**历史通俗建议：**

```
卷 / 全书
  └─ 篇章(Chapter)              ← 一个历史阶段 / 一个主题（如“万历十五年”）
       └─ 叙事块(Narrative Block) ← 一次完整事件闭环
            ├─ 情境单元(Context Unit)
            ├─ 事件单元(Event Unit)
            ├─ 人物心理/动机单元(Actor Unit)
            ├─ 结构分析单元(Structure Unit)
            └─ 反思/升华单元(Reflection Unit)
```

> **叙事块**是最小生成原子，相当于科普里的「说理单元」。

## 六、生产链条复盘（历史通俗示例）

**输入**：事件「万历十五年·申时行的困境」，目标风格「黄仁宇式」

**冷启动**：

- 标签：`#character_dilemma #institutional_analysis #structural_reveal`
- 绑定文风包 `cp_history_huang_renyu_v1`
- 张力弧线：`narrative_hook → slow_buildup → dramatic_irony → structural_reveal`

**全自动生产**：

1. 规则引擎调取事件、人物特质、制度背景
2. 按叙事块模板组装单元顺序：
   - 情境单元：当日朝会气氛（`slow_buildup`）
   - 人物单元：申时行内心权衡（`dramatic_irony`：读者知体制无解）
   - 事件单元：他选择调和而非激进（`climax_decision`）
   - 结构单元：从个人困境上升到文官集团与皇权结构性矛盾（`structural_reveal`）
3. 文风包注入：
   - 连接词：「由此观之」「若从制度层面审视」
   - 句式：中长句，适度被动语态
   - 语气：冷静分析，隐含反讽
4. 输出：
   - 结构化章节草稿
   - 自动标注 `#boxed_context`（如“明代内阁制度简介”）
   - 可选：时间轴 JSON、人物关系图 DOT

## 八、一个关键设计建议：双轨叙事模板

历史通俗作品强烈建议引入**双轨模板**：

```
[叙事轨] 事件 → 人物 → 冲突 → 结局
[分析轨] 制度 → 结构 → 长周期因果
```

- 模板控制：**何时从叙事轨跳到分析轨**（如黄仁宇的“大历史”跳跃）
- 文风包控制：**两轨语气是否一致**（通俗版两轨都口语化；学术通俗版叙事轨生动、分析轨冷静）

> 这在你们体系中可形式化为：
>
> ```yaml
> template_rule:
>   after_event_unit: insert_structure_unit
>   transition_marker: random_from: lexical_pool.transition_to_macro
> ```

### TPL-01｜「小事撬动大局」模板（黄仁宇式）

**适用**：制度史、政治史、长周期因果分析

**核心逻辑**：微观事件 → 宏观结构

```
叙事块结构：
[情境单元] 日常/边缘事件（一封奏折、一次迟到）
[事件单元] 事件被制度放大
[人物单元] 当事人无力感
[结构单元] 揭示制度/财政/军事深层矛盾
[反思单元] “这不是一个人的失败，而是一个系统的宿命”
```

**关键约束**

```yaml
required_tags: [#micro_event, #institutional_constraint]
forbidden_tags: [#heroic_triumph]
transition_rule: event_unit → structure_unit (mandatory)
style_injection:
  structure_unit: use_macro_language, avoid_moral_judgment
```

**张力弧线**

`narrative_hook → slow_buildup → dramatic_irony → structural_reveal`

**示例**

> 万历十五年，一封关于官员考核的普通奏折，暴露出整个文官集团与皇权的结构性死结。

`neutral_setup → divergent_views → structural_inevitability → tragic_ambiguity`

**示例**

> 崖山海战：一边是“君臣死社稷”的悲壮，一边是“结束分裂、统一中国”的逻辑。

   - 制度矛盾 → TPL-01

   - 文明对比 → TPL-04

5. **校验阶段**：检查是否违反模板约束（如TPL-01中不能出现英雄主义标签）

**问题详情：**

设计"模板选择器"的匹配规则——给定知识点，如何自动推荐最合适模板？

---

好，这个问题非常关键。

**模板选择器（Template Selector）**​ 是你这套体系的「导演」。它不直接写内容，但它决定了：

> *这个知识点，应该用哪一种「讲故事的方式」来讲。*

下面我给你设计的是一个**可解释、可审计、可扩展**的匹配规则系统，而不是黑箱的 ML 分类器——这符合你们「强约束 + 白盒」的一贯哲学。

---

# 模板选择器（Template Selector）· 匹配规则设计

## 一、核心设计原则

1. **规则驱动，而非概率驱动**​
   用 if-then / scoring 规则，不用 embedding similarity 或 LLM 自由判断。
2. **输入是「知识点 + 标签」，输出是「模板 ID + 置信度」**
3. **可回滚、可人工干预**​
   编辑可以 override 自动选择，系统记录 override 原因。
4. **支持多模板组合**（一章 = 多个叙事块串联）

---

## 二、输入：知识点的结构化表示

选择器只看**结构化字段**，不看自由文本。

## 三、匹配引擎：三层漏斗模型

```
Layer 1：硬性过滤（Hard Filter）
  ↓ 淘汰明显不匹配

  ↓ 计算最佳匹配
Layer 3：语境修正（Contextual Adjustment）
  ↓ 考虑章节位置、前后文、史观参数

**目的**：先把 10 个模板筛到 2–3 个候选。

      "required_labels": {
        "content": ["#decision_point"],
        "actor": ["#individual_agency"]
      },
      "forbidden_labels": ["#structural_determinism"],
      "min_scale": "#single_incident"

### 4.2 过滤逻辑（伪代码）

```python
candidates = all_templates
for tpl in all_templates:
    if not match_required_labels(tpl.preconditions.required_labels):
        candidates.remove(tpl)
    if has_any_forbidden_label(tpl.preconditions.forbidden_labels):
        candidates.remove(tpl)
    if node.scale < tpl.preconditions.min_scale:
        candidates.remove(tpl)
    if tpl.preferred_node_type and node.node_type != tpl.preferred_node_type:
        candidates.remove(tpl)
```

## 五、Layer 2：加权评分模型（Scoring Model）

对候选模板进行**维度打分**，总分最高者胜出。

### 5.1 评分维度（Dimensions）

| 维⁠度 | 权⁠重 | 说⁠明 |
| --- | --- | --- |
| 标⁠签⁠重⁠合⁠度 | 40% | 知⁠识⁠点⁠标⁠签 vs 模⁠板⁠偏⁠好⁠标⁠签 |
| 结⁠构⁠契⁠合⁠度 | 25% | 节⁠点⁠关⁠系（因⁠果⁠链、对⁠比⁠关⁠系⁠等） |
| 叙⁠事⁠潜⁠力 | 20% | 是⁠否⁠存⁠在⁠戏⁠剧⁠性⁠反⁠讽、张⁠力⁠等 |
| 史⁠料⁠支⁠撑⁠度 | 10% | 一⁠手⁠史⁠料⁠数⁠量⁠是⁠否⁠支⁠撑⁠深⁠度⁠分⁠析 |
| 史⁠观⁠匹⁠配⁠度 | 5% | 模⁠板⁠隐⁠含⁠史⁠观 vs 项⁠目⁠史⁠观⁠参⁠数 |

### 5.2 标签重合度（Label Overlap Score）

```python
def label_overlap_score(node_labels, tpl_preferred_labels):
    score = 0
    for category in tpl_preferred_labels:
        intersection = len(set(node_labels[category]) & set(tpl_preferred_labels[category]))
        union = len(set(node_labels[category]) | set(tpl_preferred_labels[category]))
        score += (intersection / union) if union > 0 else 0
    return normalize(score)
```

**示例**：

- TPL-01 偏好：`#institutional_constraint`, `#micro_event`, `#systemic_trap`
- 节点标签：包含 `#institutional_constraint`, `#micro_event`
- → 高重合度得分

### 5.3 结构契合度（Structural Fit Score）

考察节点在知识图谱中的位置：

```python
def structural_fit_score(node, tpl):
    score = 0
    if tpl.id == "TPL_01" and node.relations.part_of:
        score += 0.3  # 属于更大历史进程
    if tpl.id == "TPL_02" and node.relations.contradicts:
        score += 0.4  # 存在对立叙事
    if tpl.id == "TPL_04" and len(node.relations.compares_with or []) > 0:
        score += 0.5  # 有可比对象
    return score
```

### 5.4 叙事潜力（Narrative Potential Score）

```python
def narrative_potential_score(node):
    score = 0
    if "#dramatic_irony" in node.labels.narrative_potential:
        score += 0.4
    if "#moral_dilemma" in node.labels.narrative_potential:
        score += 0.3
    if node.meta.data_richness == "high":
        score += 0.3
    return min(score, 1.0)
```

### 5.5 综合评分公式

```
FinalScore(tpl) =
  0.4 × LabelOverlap
+ 0.25 × StructuralFit
+ 0.2 × NarrativePotential
+ 0.1 × SourceRichness
+ 0.05 × HistoriographyMatch
```

# 篇章编排语法（COG）V1.0

## —— 历史通俗作品的“乐谱”

---

## 一、基本哲学：章节 ≠ 模板堆砌，而是「叙事弧线」

一章的结构，本质上是**读者认知过程的建模**：

```
引入张力 → 深化冲突 → 结构跃升 → 长时段回响
```

每个模板是**一个和弦**，组合策略是**和弦进行**。

## 二、最小编排单元：Section（节）

    "knowledge_node": "event_wanli_15_zhangju_zheng",
    "tension_weight": 0.7,
    "pacing": "slow_buildup"
  }
}
```

| 角⁠色 | 定⁠义 | 常⁠用⁠模⁠板 |
| --- | --- | --- |
| `anchor_event` | 锚⁠定⁠事⁠件，章⁠节⁠起⁠点 | TPL-01, TPL-02 |
| `deep_dive` | 深⁠入⁠制⁠度/心⁠理⁠内⁠部 | TPL-03, TPL-05 |
| `counterpoint` | 提⁠供⁠对⁠立/修⁠正⁠视⁠角 | TPL-08, TPL-10 |
| `macro_frame` | 提⁠供⁠长⁠时⁠段/结⁠构⁠框⁠架 | TPL-04, TPL-09 |
| `synthesis` | 综⁠合⁠前⁠文，升⁠华⁠主⁠题 | TPL-06, TPL-07 |
| `bridge` | 承⁠上⁠启⁠下 | TPL-01（弱⁠化⁠版） |

## 五、经典编排模式（Canonical Patterns）

### Pattern A：「微观→修正→宏观」（你指定的路线）

> **适用**：制度史、政治史、需要翻案或重构认知的章节

```
TPL-01 (anchor_event)
  ↓ [认知对比：常识 vs 新证据]
TPL-08 (revisionist_counterpoint)
  ↓ [时间膨胀：瞬间 → 世纪]
TPL-09 (longue_duree_context)
```

**张力曲线**

```
低（日常）→ 中（反转）→ 高（宏大宿命）
```

**示例章节：《万历十五年的三张面孔》**

1. **TPL-01**：一本奏折引发的行政僵局（常识叙事）
2. **TPL-08**：但这并非皇帝昏庸，而是财政技术缺失（修正叙事）
3. **TPL-09**：这种技术缺失，源于两百年农业税收结构的缓慢固化（长时段根源）

---

### Pattern B：「抉择→悲剧→结构」（人物悲剧弧）

> **适用**：变法失败、忠臣悲剧、改革者故事

```
TPL-02 (decisive_moment)
  ↓ [结构压迫感增强]
TPL-03 (system_kills_individual)
  ↓ [观念/制度反思]
TPL-06 (idea_birth)
```

**张力曲线**

```
高（抉择）→ 极高（毁灭）→ 中（反思）
```

---

### Pattern C：「碰撞→后果→复调」（文明/阶级冲突）

> **适用**：战争史、殖民史、社会变革

```
TPL-04 (civilization_clash)
  ↓ [社会重组分析]
TPL-05 (tech_changes_society)
  ↓ [多视角平衡]
TPL-10 (polyphonic_history)
```

---

### Pattern D：「沉默→发声→回响」（底层视角）

> **适用**：社会史、微观史、女性史

```
TPL-07 (forgotten_majority)
  ↓ [技术/制度解释]
TPL-05 (structural_explanation)

## 七、节奏控制：Pacing & Density

### 7.2 编排约束

```python
# 禁止连续两个高密度模板
constraint "no_double_high_density":
  not (section[i].density == "high" and section[i+1].density == "high")

# 章节中间必须有一次节奏放缓
constraint "must_have_breathing_room":
  exists section where density == "low"

# 结尾必须是中低密度（留给读者思考）
constraint "soft_ending":
  last_section.density != "high"
```

# 模板 × 角色亲和度矩阵（Role Affinity Matrix）

## —— 编排语法的“选角指南”

**设计原则：**

- 每个模板都有 **主角色（Primary Role）**​ 和 **次级角色（Secondary Role）**
- 亲和度用 **0–3 分**​ 表示：
  - `3`= 天生契合，首选
  - `2`= 可用，次选
  - `1`= 勉强可用，需人工微调
  - `0`= 违和，禁止自动选用
- 人工 override 可以无视分数，但系统会发出警告

## 二、逐模板角色语义详解

### TPL-01 小事撬动大局

- **主角色：anchor_event**
  - 最擅长作为章节的“锚点”和“切入点”
  - 把一个微小事件变成整章的叙事发动机
- **次级角色：bridge**
  - 弱化版 TPL-01 可作为章节间的过渡（如“另一件小事同样揭示了……”）
- **慎用：synthesis**
  - 它负责“提出问题”，不适合“总结全章”

### TPL-02 命运抉择时刻

- **主角色：anchor_event**
  - 以人物抉择为锚，适合传记性、政治史章节
- **次级角色：deep_dive**
  - 可深入挖掘人物心理和决策逻辑
- **禁忌：macro_frame**
  - 过于聚焦个人，不适合直接撑起宏观框架

### TPL-03 制度杀人

- **主角色：deep_dive**
  - 专门用来解剖制度如何吞噬个体
- **次级角色：anchor_event**
  - 当悲剧事件本身就是最佳切入点时使用
- **注意**
  - 情绪压抑，不宜连续使用，需搭配 lighter 模板调节节奏

### TPL-04 文明碰撞

- **主角色：macro_frame**
  - 天生适合搭建跨文化、跨文明的宏观对比框架
- **次级角色：anchor_event / deep_dive**
  - 可用具体接触事件引入，或深入分析差异根源
- **编排建议**
  - 常作为开篇章节，奠定全书比较视野

### TPL-05 技术改变社会

- **双主角色：deep_dive + macro_frame**
  - 既可深入分析技术原理，又可上升到社会结构变迁
- **次级角色：synthesis**
  - 适合在章节末尾讨论技术的双重性
- **特色**
  - 唯一一个在 `deep_dive`和 `macro_frame`上都得 3 分的模板

### TPL-06 观念诞生记

- **双主角色：deep_dive + synthesis**
  - 深入分析思想逻辑，并综合其历史影响
- **次级角色：counterpoint**
  - 可与旧观念对比，突出新思想的新颖性
- **禁忌：anchor_event**
  - 观念诞生往往是漫长过程，不适合作为具体事件锚点

### TPL-07 被遗忘的多数

- **双主角色：counterpoint + bridge**
  - 作为主流叙事的对立面，或舒缓宏大叙事节奏的“呼吸段”
- **编排价值**
  - 防止章节过于精英化、男性化、政治化
  - 在密集分析后提供人文温度

### TPL-08 历史反转

- **主角色：counterpoint**
  - 专门负责修正认知、打破常识
- **次级角色：bridge / synthesis**
  - 可连接新旧叙事，或在章节末尾提供修正后的综合视角
- **编排建议**
  - 常紧跟在 TPL-01 或 TPL-02 之后，形成“常识 → 反转”的认知冲击

### TPL-09 长时段缓慢变化

- **主角色：macro_frame**
  - 提供最深的时间纵深和最大尺度
- **次级角色：deep_dive**
  - 可深入分析缓慢变化的具体机制（如气候、土壤）
- **禁忌：anchor_event**
  - 事件在其中极其渺小，不适合作为章节起点
- **编排建议**
  - 常作为章节或全书的结尾，提供宿命感和哲学反思

### TPL-10 复调历史

- **主角色：counterpoint**
  - 提供多视角并置，打破单一叙事
- **次级角色：bridge / synthesis**
  - 连接不同视角，或综合出更复杂的图景
- **特色**
  - 唯一一个在 `counterpoint`上得 3 分且适合收尾的模板

## 三、基于矩阵的自动编排算法（简化版）

有了矩阵，规则引擎就可以自动“选角”了。

### 3.1 章节角色序列预设（Chapter Role Sequence）

```yaml
chapter_archetypes:
  archetype_a_micro_macro:
    description: "微观→修正→宏观（你指定的路线）"
    sequence: [anchor_event, counterpoint, macro_frame]
    recommended_ids: [TPL-01, TPL-08, TPL-09]

  archetype_b_tragedy:
    description: "抉择→毁灭→反思"
    sequence: [anchor_event, deep_dive, synthesis]
    recommended_ids: [TPL-02, TPL-03, TPL-06]

  archetype_c_clash:
    description: "碰撞→变革→复调"
    sequence: [macro_frame, deep_dive, counterpoint]
    recommended_ids: [TPL-04, TPL-05, TPL-10]

  archetype_d_social_history:
    description: "沉默→结构→发声"
    sequence: [counterpoint, deep_dive, synthesis]
    recommended_ids: [TPL-07, TPL-05, TPL-08]
```

### 3.2 自动选角逻辑（Pseudocode）

```python
def auto_cast(chapter_archetype, available_knowledge_nodes):
    selected_sections = []
    for role in chapter_archetype.sequence:
        # 1. 筛选亲和度 >= 2 的模板
        candidate_templates = [
            tpl for tpl in all_templates
            if affinity_matrix[tpl.id][role] >= 2
        ]
        # 2. 结合知识点标签和模板 precondition 进一步筛选
        suitable_templates = filter_by_preconditions(candidate_templates, available_knowledge_nodes)
        # 3. 如果有多个，选亲和度最高的；如果亲和度相同，选评分最高的
        best_tpl = select_best_template(suitable_templates, role)
        # 4. 从知识点池中匹配最合适的节点
        best_node = match_best_node(best_tpl, available_knowledge_nodes)
        # 5. 创建 Section
        section = create_section(template=best_tpl, node=best_node, role=role)
        selected_sections.append(section)
    return selected_sections
```

## 四、冲突消解与人工干预

### 4.1 常见冲突

1. **角色争抢**：两个知识点都最适合做 `anchor_event`
   - **解法**：选时间更早的；选史料更丰富的；人工指定
2. **模板重复**：连续两个 Section 都选了 TPL-01
   - **解法**：系统自动将第二个降级为 `bridge`角色，或替换为 TPL-08
3. **亲和度不足**：某个角色找不到亲和度 >= 2 的模板
   - **解法**：放宽到亲和度 1，并发出警告；请求人工介入

## 五、这套矩阵如何让系统“会编导”

现在，你的系统具备了：

1. **选角能力**：知道每个模板适合演什么“角色”
2. **排戏能力**：知道一个章节应该有哪些“角色”（角色序列）
3. **调度能力**：能在知识点池中为每个角色找到最合适的“演员”（知识点+模板实例）
4. **纠错能力**：能发现角色冲突、模板重复等问题

**举个完整例子：**

> **目标**：写一章关于“王安石变法”的内容，采用 `archetype_b_tragedy`（抉择→毁灭→反思）模式。

**系统自动编排：**

1. **anchor_event**：
   - 候选模板：TPL-01 (3), TPL-02 (3)
   - 选中：TPL-02（命运抉择时刻）
   - 知识点：熙宁二年，王安石与司马光廷辩，宋神宗最终拍板支持变法
2. **deep_dive**：
   - 候选模板：TPL-03 (3), TPL-05 (3)
   - 选中：TPL-03（制度杀人）
   - 知识点：青苗法在执行中被官僚体系扭曲，从“惠民”变为“害民”的机制分析
3. **synthesis**：
   - 候选模板：TPL-06 (3), TPL-08 (2)
   - 选中：TPL-06（观念诞生记）
   - 知识点：变法失败后，“改革”与“保守”观念在后世的长久回响与误读

**输出**：一个结构完整、张力合理、符合悲剧叙事弧线的章节草案。

## 二、模块一：史观参数包（Historiography Profile）

> 解决「价值观和情绪的注入、立场问题」

### 1. 为什么不能是“文风包”顺带干这事？

- 文风包管的是**怎么说**（口语化？书面化？爱用破折号？）
- 史观包管的是**说什么、站在哪边、褒谁贬谁**

如果把“同情农民起义”塞进文风包，会导致：

- 史观变了，却要重建文风包
- 同一文风（比如“通俗讲故事”）可以承载完全不同的立场

所以：**史观 ≠ 文风，必须拆开。**

---

### 2. 史观参数包的结构化设计

```yaml
historiography_profile:
  profile_id: "structural_materialist_v1"
  display_name: "结构唯物主义史观"

  # ① 核心立场向量（可量化、可审计）
  stance_vector:
    individual_agency: -0.3        # 个人作用权重（负：结构为主）
    structural_determinism: 0.8     # 结构决定论强度
    moral_judgment: -0.7           # 道德评判倾向（负：少道德化）
    great_man_theory: -0.8         # 英雄史观（负：反对）
    popular_agency: 0.6            # 群众能动性

  # ② 情绪基调（全局情绪底色）
  emotional_tone:
    default: "sober_detached"      # 冷静、略带悲观
    toward_power: "skeptical"
    toward_the_vulnerable: "empathetic_but_not_sentimental"

  # ③ 价值观关键词（用于约束生成）
  value_keywords:
    approved: ["制度困境", "结构性矛盾", "技术治理", "路径依赖"]
    discouraged: ["昏庸", "奸佞", "圣明", "天意"]
    forbidden: ["种族优劣", "历史宿命论（非结构性）"]

  # ④ 与模板的联动规则
  template_bias:
    TPL_01: +0.2      # 偏好“小事撬动大局”
    TPL_03: +0.2      # 偏好“制度杀人”
    TPL_02: -0.3      # 降低“命运抉择”（个人英雄）
    TPL_09: +0.1      # 偏好“长时段”

  # ⑤ 情绪注入规则（这是你说的“情绪注入”）
  emotion_injection:
    toward_systemic_tragedy: "quiet_sorrow"
    toward_individual_struggle: "restrained_respect"
    toward_irony_of_history: "subtle_irony_no_laughter"
```

👉 **关键点**：

这个文件一旦确定，整本书的“立场”就白盒化了。编辑可以争论、修改、存档，而不是藏在作者的潜意识里。

```

### 2. 连接点挖掘规则（Connection Point Rules）

这是你体系里非常有创造力的一块：**让机器“主动”找共鸣**。

#### （1）知识连接点（Cognitive Bridge）

规则：当知识点属于 `unknown`或 `fuzzy`时，必须通过一个 `solid`领域的类比来引入。

```python
def find_cognitive_bridge(knowledge_node, reader_persona):
    if knowledge_node in reader_persona.knowledge_assumptions.history.unknown:
        # 从读者熟悉的领域找类比
        analogies = search_analogy_pool(
            target_concept=knowledge_node,
            source_domains=reader_persona.cognitive_style.prefers_analogy_from
        )
        return select_best_analogy(analogies)
```

**示例**：

- 知识点：`明代内阁票拟制度`
- 读者熟悉：`公司审批流程 / 项目管理`
- 生成连接点：
  > “你可以把明代内阁想象成一个没有最终签字权的‘总经办’，所有方案都要送到皇帝——这位永远‘已读不回’的董事长——那里。”

#### （2）情感连接点（Emotional Bridge）

规则：识别知识点的潜在情感张力，匹配读者情感原型。

```python
def find_emotional_bridge(knowledge_node, reader_persona):
    node_emotion = extract_emotional_tone(knowledge_node)  # e.g., systemic_frustration
    if node_emotion in reader_persona.emotional_archetype.resonates_with:
        return craft_emotional_opening(node_emotion)
```

**示例**：

- 知识点：`申时行在两大势力间艰难平衡`
- 读者情感原型：`职场夹心层`
- 生成连接点：
  > “如果你是那个既要完成老板指标，又要安抚团队情绪的部门经理，你会理解申时行那种深夜批阅奏折时的无力感。”

# 心理动力学编排层（PDL）

## —— 让历史通俗作品“全程无尿点”的工程化方案

### 核心命题

> 如何用**可参数化、可审计的规则**，模拟剧本/小说的**悬念构建、矛盾烘托、情绪起伏**，让读者产生“追更”冲动？

---

## 一、先对齐一个前提：历史 ≠ 小说，但可以借用“剧作结构”

| 维⁠度 | 小⁠说 / 剧⁠本 | 历⁠史⁠通⁠俗⁠作⁠品 | 本⁠体⁠系⁠应⁠对⁠策⁠略 |
| --- | --- | --- | --- |
| 情⁠节 | 可⁠虚⁠构 | 不⁠可⁠虚⁠构 | ✅ **挖⁠掘⁠真⁠实⁠事⁠件⁠中⁠的“戏⁠剧⁠性⁠反⁠讽”** |
| 冲⁠突 | 可⁠设⁠计 | 已⁠存⁠在 | ✅ **放⁠大⁠结⁠构⁠冲⁠突、认⁠知⁠冲⁠突** |
| 悬⁠念 | 信⁠息 withholding | 认⁠知⁠落⁠差 | ✅ **利⁠用“后⁠见⁠之⁠明”制⁠造⁠悬⁠念** |
| 人⁠物 | 可⁠塑 | 既⁠定 | ✅ **深⁠挖⁠动⁠机⁠困⁠境、选⁠择⁠张⁠力** |

**结论**：

历史本身的戏剧性往往被平淡的叙述掩盖了。我们的任务不是编造，而是**重新发现并结构化地呈现**。

---

## 二、把“剧本手法”翻译成模板系统的语言

我们从经典剧作理论（三幕式、救猫咪、斯奈德节拍表）中提取**可工程化的元素**：

### 1. 悬念（Suspense） → 「认知落差槽」

**剧本手法**：观众知道炸弹在桌下，角色不知道。

**历史对应**：**读者知道历史结局，人物不知道。**

#### 在模板中的落地（以 TPL-01 为例）

新增槽位：

```json
{
  "unit_type": "context_unit",
  "fill_slots": {
    "dramatic_irony_marker": {
      "required": true,
      "description": "明确指出读者已知、但人物未知的信息",
      "example": "此时，申时行并不知道，这一封奏折将在十七年后，成为萨尔浒之战溃败的注脚。"
    }
  }
}
```

**规则引擎约束**：

- 每个 `anchor_event`模板实例，**必须**包含一个 `dramatic_irony_marker`
- 位置：通常在单元结尾，制造“回响感”

---

### 2. 矛盾烘托（Conflict Escalation） → 「张力阶梯」

**剧本手法**：压力层层加码，直到不可承受。

**历史对应**：**制度压力、道德困境、资源约束的逐级收紧。**

#### 在编排语法（COG）中的落地

新增章节级属性：

```yaml
chapter:
  tension_profile:
    type: "escalating"
    stages:
      - section: sec_01
        tension_level: 0.3
        pressure_source: "routine_administrative_issue"
      - section: sec_02
        tension_level: 0.6
        pressure_source: "institutional_backlash"
      - section: sec_03
        tension_level: 0.9
        pressure_source: "systemic_collapse"
```

**规则**：

- 禁止 `tension_level`连续下降（除非刻意制造“虚假安全感”）
- 每个 Section 的 `pressure_source`必须与前一节构成**递进或转化关系**

---

### 3. 高潮（Climax） → 「结构跃升点」

**剧本手法**：所有矛盾汇聚，主角做出不可逆抉择。

**历史对应**：**从具体事件跃升至结构性解释的时刻（TPL-01 的 Structure Unit）。**

#### 在模板中的特殊标记

```json
{
  "unit_type": "structure_unit",
  "is_chapter_climax": true,
  "climax_attributes": {
    "insight_type": "paradigm_shift",  // 范式转移
    "emotional_payload": "tragic_inevitability",
    "pacing": "slow_unfolding"  // 高潮不是快，而是慢、沉、重
  }
}
```

**规则引擎**：

- 每个 Chapter 必须有且仅有一个 `is_chapter_climax: true`的单元
- 该单元前后必须有明显的**节奏变化**（前紧后松，或前快后慢）

---

### 4. 节奏呼吸（Pacing & Breathing） → 「密度交替规则」

**剧本手法**：动作戏后必有文戏，让观众喘口气。

**历史对应**：**高密度分析后，插入感性、微观或复调段落。**

#### 在 COG 中的强化规则

```python
# 原有规则强化
constraint "dynamic_breathing_room":
  # 高密度单元后，必须跟一个中或低密度单元
  for i in range(len(sections)-1):
    if sections[i].density == "high":
      assert sections[i+1].density in ["medium", "low"]
    # 但连续三个中密度也需要一次低密度
    if i >= 2 and all(sections[j].density == "medium" for j in range(i-2, i+1)):
      assert sections[i+1].density == "low"
```

**低密度单元的最佳候选**：

- TPL-07（被遗忘的多数）：人文温度
- TPL-10（复调历史）：视角转换
- TPL-02 的 `actor_unit`：心理描写

### 5. 钩子（Hook） → 「章节首尾呼应」

## 四、一个全新的编排模式：「追更型章节（Page-Turner Chapter）」

基于上述所有改造，我们定义一个**专门用于“抓人心”的章节编排模式**：

```yaml
archetype_page_turner:
  description: "高悬念、强节奏、情绪过山车"
  sequence: [anchor_event, deep_dive, counterpoint, macro_frame]
  psychological_dynamics:
    opening_hook: "dramatic_irony"  # 开篇即点明结局的可怕
    tension_curve: "sharp_rise_then_slow_burn"
    breathing:
      after_high_density: "insert_TPL_07_for_human_touch"
    climax:
      unit: "structure_unit_of_TPL_01_or_TPL_09"
      pacing: "slow_and_heavy"
    ending_hook:
      type: "foreshadowing"
      emotional_tone: "foreboding"
  required_elements_per_section:
    anchor_event:
      - dramatic_irony_marker
      - ticking_clock (if applicable)
    deep_dive:
      - stakes_clarity
      - emotional_pressure
    counterpoint:
      - cognitive_dissonance
    macro_frame:
      - tragic_inevitability
```

**示例章节：《崇祯：最后的十七年》**

1. **开篇 Hook**：1644年三月十八日夜，崇祯不知道这是他生命的最后一夜。（戏剧性反讽）
2. **TPL-01（Anchor）**：一封关于粮草短缺的奏折，如何暴露整个后勤系统的崩溃。（小事撬动大局 + 滴答钟声）
3. **TPL-03（Deep Dive）**：崇祯的勤勉如何被低效的官僚制度吞噬。（矛盾层层加码）
4. **TPL-07（Breathing）**：一个守城士兵的日记，记录物价飞涨和绝望。（情感连接点，低密度）
5. **TPL-08（Counterpoint）**：并非亡于“昏君”，而是亡于“财政技术的彻底破产”。（历史反转，认知颠覆）
6. **TPL-09（Macro Frame / Climax）**：这一崩溃，早在百年前张居正改革未能触及财政根基层时便已注定。（结构跃升，慢速高潮）
7. **结尾 Hook**：当李自成的军队攻入北京时，他们面临的，是同一个无法解决的结构性难题。（预示下一章：新政权的困境）

## 四、选材评分公式（Selection Scoring）

给定：

- 叙事意图 `INTENT`
- 史观包 `HP`（含 stance_vector）
- 读者画像 `RP`（含 typical_reader_resonance）

对每个候选节点计算 `SelectionScore`：

```
S = α·IntentFit
  + β·DramaticPotential
  + γ·SourceQuality
  + δ·ReaderResonance
  + ε·HistoriographyBias
```

### 各项说明

| 项 | 含⁠义 | 典⁠型⁠权⁠重 |
| --- | --- | --- |
| `IntentFit` | 节⁠点 narrative_fit_tags 含 INTENT → 1，否⁠则⁠降⁠权 | α=0.35 |

## 五、选材流程（Selection Pipeline）

```text
① 确定服务目标（INTENT）
   ↓
② 从知识库中拉取候选节点（按时期/主题过滤）

   ↓

   ↓

```

# 收束补丁一：冲击力注入层（Impact Injection Layer）

## —— 让“惊人事实”成为叙事的鼓点

### 1. 本质定义

> **冲击力 = 反常识密度 × 数据精确性 × 情绪唤醒度**

它不是“标题党”，而是**在正确位置，用正确方式，释放被平淡叙述掩盖的真实震撼**。

### 2. 知识节点新增字段

```json
{
  "knowledge_node": {
    "impact_potential": {
      "counter_intuitive_score": 0.9, // 0–1，越反常识越高
      "precision_data": {
        "value": "国库仅剩白银 2300 两",
        "context": "尚不足皇室一日脂膏",
        "source": "《明实录·崇祯朝》"
      },
      "emotional_valence": "shock_and_despair",
      "memorable_phrase_seed": "一座皇城的价码，不过两千两"
    }
  }
}
```

### 3. 冲击力投放规则（Placement Rules）

冲击力不能随意撒，必须**卡在叙事的“穴位”上**。

| 投⁠放⁠位⁠置 | 作⁠用 | 规⁠则 |
| --- | --- | --- |
| **开⁠篇 Hook** | 瞬⁠间⁠抓⁠住⁠注⁠意⁠力 | 若⁠为 `dramatic_irony`场⁠景，优⁠先⁠使⁠用⁠高 `counter_intuitive_score`数⁠据 |
| **矛⁠盾⁠升⁠级⁠点** | 加⁠剧⁠张⁠力 | 在 `tension_level`上⁠升⁠阶⁠段，插⁠入 `precision_data` |
| **高⁠潮⁠前⁠静⁠默** | 制⁠造“窒⁠息⁠感” | 在 Climax 单⁠元⁠前，用⁠极⁠简⁠数⁠据⁠打⁠断⁠抒⁠情 |
| **结⁠尾 Hook** | 留⁠下⁠余⁠震 | 用 `precision_data`指⁠向⁠当⁠下，形⁠成“一⁠切⁠历⁠史⁠都⁠是⁠当⁠代⁠史”的⁠回⁠响 |

# 收束补丁二：主旋律记忆层（Melodic Motif Layer）

## —— 让“一切历史都是当代史”成为读者的记忆锚点

你提到的这一点非常深刻：**历史作品最终留在读者脑子里的，往往不是细节，而是一两句“旋律”**。

### 1. 定义“主旋律”（Motif）

> **主旋律 = 贯穿全篇的、可被反复感知的、最终沉淀为认知或警句的核心命题。**

它可以是：

- **一个规律**（如“技术治理的缺失必然导致系统崩溃”）
- **一个反差**（如“越勤奋，越失败”）
- **一个当代映射**（如“KPI 压垮组织”）

### 2. 史观包升级：主旋律定义

```yaml
historiography_profile:
  profile_id: "structural_materialist_v1"
  core_motif:
    statement: "缺乏技术治理支撑的道德教化，终将沦为系统性谎言。"
    contemporary_echo: "现代组织的 KPI 崇拜，若缺乏底层数据支撑，亦是另一种道德教化。"
    emotional_color: "sober_warning"
    recurrence_frequency: "per_chapter" # 每章至少出现一次
```

### 3. 主旋律的“复现机制”（Leitmotif Technique）

借鉴瓦格纳歌剧和电影配乐的手法，主旋律需要**变奏出现**，而不是简单重复。

| 复⁠现⁠场⁠景 | 变⁠奏⁠形⁠式 | 示⁠例 |
| --- | --- | --- |
| **章⁠节⁠开⁠篇** | 陈⁠述⁠式 | “这⁠又⁠是⁠一⁠个⁠试⁠图⁠用⁠道⁠德⁠填⁠补⁠技⁠术⁠真⁠空⁠的⁠故⁠事。” |
| **矛⁠盾⁠激⁠化** | 反⁠问⁠式 | “当⁠流⁠程⁠只⁠剩⁠道⁠德⁠口⁠号，谁⁠来⁠填⁠补⁠那 2300 两⁠白⁠银⁠的⁠亏⁠空？” |
| **高⁠潮⁠结⁠构⁠单⁠元** | 论⁠断⁠式 | “这⁠就⁠是⁠结⁠构⁠性⁠困⁠境⁠的⁠本⁠质：道⁠德⁠是⁠锦⁠上⁠添⁠花，技⁠术⁠是⁠雪⁠中⁠送⁠炭。” |
| **结⁠尾⁠反⁠思** | 警⁠句⁠式 | **“历⁠史⁠从⁠不⁠重⁠复，但⁠缺⁠乏⁠技⁠术⁠底⁠座⁠的⁠宏⁠大⁠叙⁠事，总⁠会⁠以⁠相⁠似⁠的⁠方⁠式⁠塌⁠方。”** |

### 4. 在编排语法（COG）中的落地

## 【阶段二】选材 · 决定讲什么故事（历史作品特有）

### 3. 选材引擎（Material Selection & Weighting）

- 按 **Narrative Intent × 史观包 × 读者画像**​ 对知识节点评分
- `SelectionScore = IntentFit + DramaticPotential + SourceQuality + ReaderResonance + HP Bias`
- 施加约束（时间序、视角平衡、史料最低标准）
- 允许编辑 **pin / boost / exclude**（把作者品味参数化）

> ✅ 解决「选材自由度与加权自由度」问题

---

## 【阶段三】编排 · 决定怎么讲故事

### 4. 模板选择器

- 根据节点标签、规模、叙事潜力匹配模板
- 按角色矩阵（anchor_event / deep_dive / counterpoint / macro_frame…）评分
- 章节位置、史观 bias、前后文去重修正

### 5. 章节编排语法（COG）＋心理动力学层（PDL）

- 编排模板序列（例：TPL-01 → TPL-08 → TPL-09）
- 注入：
  - **悬念**：认知落差槽（读者知结局，人物不知）
  - **矛盾烘托**：张力阶梯（pressure_source 逐级加码）
  - **高潮**：结构跃升点（事件→制度解释）
  - **节奏呼吸**：高密度分析 ↔ 低密度人文段落
  - **钩子**：章末 foreshadowing（追更欲）
- **冲击力注入**：反常识精确数据在叙事穴位敲入
- **主旋律（Motif）复现**：每章变奏出现核心命题 + 当代映射（一切历史都是当代史）

> ✅ 解决「全程无尿点 / 悬念构建 / 记忆锚点」问题

---

## 【阶段四】全自动生产 · 边际成本趋零

### 6. 受控生成

- 每模板单元 = **LLM 填槽（选择题/填空题），非自由创作**
- 注入：史观禁用词、文风包（连接词/句式/比喻密度）、情绪弧线、读者连接点（认知桥＋情感桥）

### 7. 校验 & 输出

- 模板级约束（微观事件必须 trivial、禁止英雄叙事…）

- 输出：结构化 Markdown / 讲义 / SSML 脚本 / 动画分镜标签

## 一、「审美」在这里的准确定义

你用的“审美”是广义的、工程可拆解的：

> **审美 = 对“一部好作品是什么样子”的完整、显性、可参数化的定义。**

- **内容维度**：结构是否合理？概念依赖是否清晰？是否有认知跃升？
- **表现力维度**：文风是否一致？情绪弧线是否到位？主旋律是否被记住？
- **读者维度**：是否和读者已有认知/情感产生桥接？是否在其知识边界上拉伸而非碾压？

- ✅ 模板结构

- ✅ 史观包
- ✅ 读者画像
- ✅ 冲击力 / 主旋律规则
- ✅ 张力曲线约束

**这就是“把审美形式化”。**

## 一、先给结论：在这个场景下，对抗 Agent 解决什么问题？

你这套体系目前最强的是**“正向约束”**：

- 模板保证结构
- 文风包保证语气
- 史观包保证立场
- PDL 保证节奏
- 选材引擎保证“讲什么”

但正向约束有一个**天然盲区**：

> **它只能保证“没写错”，不能保证“写得好”；
>
> 更不能保证“在读者眼里站得住脚”。**

对抗 Agent 的核心价值，就是**站在“批评者 / 读者 / 对手”的立场上，主动挑刺、施压、攻击**，倒逼系统产出更结实的内容。

### 推荐位置：**编排后、渲染前（核心关卡）**

```

  ↓

  ↓

  ↓

  ├─ ② Reader Advocate
  ├─ ③ Narrative Critic
  ├─ ④ Integrity Guardian
  └─ ⑤ Perspective Challenger
  ↓
（若通过）→ 进入渲染
（若不通过）→ 返回修改（调整选材 / 模板 / 张力 / 连接点）
  ↓
受控渲染（LLM 填槽）
  ↓

## 三、「风格形成」在工程上是怎样的过程？

这是你问中最精妙的一点——**风格不是“像”，而是“受控重复 + 受控变异”**。

### 1. 受控重复（Repetition → 辨识度）

以下元素**每部书、每章必须出现**，形成“听到/看到就知道是你”：

- ✅ 同一主旋律（Motif）变奏出现
- ✅ 同一文风包（词汇池/句式/比喻偏好）
- ✅ 同一史观底色（结构性解释优先）
- ✅ 同一模板角色偏好（TPL-01 开场）
- ✅ 同一冲击力处理方式（反常识数据＋不煽情）
- ✅ 同一章末“当代映射”钩子

> 读者读完三本后，会下意识感觉：
>
> **“这是那个用结构看历史、冷静但有人味的系列。”**

### 2. 受控变异（Variation → 不平庸，防机械）

以下元素**允许 / 要求每部书不同**，避免千篇一律：

| 维⁠度 | 变⁠异⁠规⁠则 |
| --- | --- |
| 选⁠材⁠范⁠围 | 每⁠部⁠书⁠不⁠同⁠朝⁠代/主⁠题（明/罗⁠马/奥⁠斯⁠曼…） |
| Narrative Intent | 书1=TRAGEDY，书2=REVISION，书3=MICRO |
| 主⁠旋⁠律⁠变⁠奏⁠深⁠度 | 书1=点⁠出，书2=展⁠开，书3=给⁠出⁠当⁠代⁠方⁠案⁠暗⁠示 |
| 读⁠者⁠微⁠调 | 书3可⁠面⁠向⁠大⁠学⁠生，书1面⁠向⁠大⁠众 |
| 个⁠别⁠文⁠风⁠参⁠数 | 书2可⁠微⁠调⁠用⁠喻⁠密⁠度＋段⁠落⁠长⁠度（但⁠仍⁠锁⁠定⁠禁⁠止⁠项） |
