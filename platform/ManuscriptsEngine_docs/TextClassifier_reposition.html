TextClassifier 重定位方案

2026-07-12 · 决策：纳入 SPDT-005 shared/smarttext_router/router/

背景

TextClassifier 创建于 2026-06-15（PP-20260615-001），定位为"文字产品生产线的统一入口路由器"。当时 SPDT 体系尚未建立（SPDT-005 成立于 2026-07-10），6 集群定义未与 PDT 对齐。

问题诊断

三方命名不一致

集群classifier.pysmarttext READMESPDT-005 PDT对齐
A快讯/短消息实时快反PT-041 FlashNews✅
B深度分析/报告深度生产PT-040 DeepProd✅
C科普/教育知识科普(E)PT-042 SciPop❌
D技术文档技术文档PT-045 TechDoc✅
E创意/评论观点论证(F)PT-043 OpEd❌
F营销/商业文案创意转化(C)PT-044 CreativeX❌

覆盖范围过大

  • C 集群包含"教育"：SPDT-004 才是教育内容的归属，TextClassifier 不应替教育产线做路由
  • E/F 边界模糊：PT-043(OpEd) 和 PT-044(CreativeX) 的分界线更清晰
  • 缺少跨 SPDT 路由：无法甄别教育类需求并转发 SPDT-004

决策

纳入 SPDT-005，作为 smarttext_router 的 router 子系统。不新建 SPDT。

集群新名称对应 PDT说明

新增：跨 SPDT 路由

输入检测到 教育学生备考课件 标签
→ 不进入 C 集群
→ 输出 cross_spdt_route: SPDT-004
→ SPDT-004 PT-031(通识教育) 接单

1

2

3
裁剪 Cluster C + 添加跨路由
C 集群移除"教育"标签匹配；新增 cross_spdt_route 检测逻辑
4
更新 golden tests
15 测试用例按新集群重新标注；增加教育类 → SPDT-004 的 case
5
同步 README
smarttext_router/README.md 集群名称一致化
6
归档原目录
D:\92_products\TextClassifier 归档；SR-TEXT-001 迁移到 smarttext_router/docs/

保留 vs 丢弃

✅ 保留
  • 4-step pipeline
  • 10 维 StructuredSpec
  • 7-rule 决策树
  • 2s 目标延迟
  • 15 golden tests + 5 edge cases
  • L2 配置模板体系
❌ 丢弃/修改
  • "教育"从 C 集群彻底移除
  • E/F 集群模糊边界 → OpEd / CreativeX
  • 独立项目身份
  • 与 PDT 不一致的集群编号
  • group_army_test 命名混淆

一句话总结

TextClassifier 的归宿是 SPDT-005 的 smarttext_router/router/——它是聪明的路由大脑，不是独立的产品线。唯二要做的：6 集群 1:1 对齐 PDT，砍掉越界的"教育"触角并加上指向 SPDT-004 的跨产品线路由。
