> 版本：V1.0
> 日期：2026-07-09

---

## 一、产品概述

### 产品定义

本平台是一套**将专家创作经验规则化、历史内容结构模板化、叙事表现力参数化**的全自动历史通俗社科作品生产系统。它把大语言模型从「创作者」降级为「受控执行器」，实现从「单次 AI 生成」到「工业级 AI 制造」的范式跃迁。

### 产品愿景

解决的核心问题：**如何持续、稳定、规模化地生产「有立场、有读者意识、有记忆锚点、全程无尿点」的历史通俗社科作品？**

当前 AI 辅助写作的普遍困境是：Prompt 工程依赖模型的概率输出，批量一致性低、表现力不可控、风格无法沉淀为资产。本平台通过将「什么是好的历史通俗作品」这一广义审美形式化为可参数化、可审计、可复用的规则体系，使「持续创作有辨识度的系列作品」从艺术灵感变为工业能力。

### 目标用户

| 用户角色 | 核心需求 | 典型场景 |
| --- | --- | --- |
| 历史内容创作者/作者 | 快速产出有专业质感的结构化草稿，保留创作主导权 | 定义史观、选材微调、文风选择 |
| 编辑/内容策划 | 把控系列作品风格一致性，降低审校成本 | 系列品牌定义、对抗评审、一致性校验 |
| 出版社/内容机构 | 批量产出多版本内容（大众版/学术版/公众号版） | 多文风包一键派生、多系列 IP 管理 |
| 内容运营团队 | 快速响应热点、衍生多模态内容 | 知识库驱动文本/音频/动画同步产出 |

### 核心理念

**强约束 + 受控多样性**。具体而言：

- **强约束**：模型只做「选择题」（选模板、填槽位），不做「作文题」（自由创作）。叙事结构、史观立场、文风基调均由规则引擎预先锁定，LLM 仅在单元内执行填槽。
- **受控多样性**：情绪注入、文风切换、结构丰度、读者连接方式等柔性变量，被显性建模为可枚举、可复用、可批量切换的参数，而非模型的随机概率输出。
- **三化原则**：专家经验规则化 + 内容结构模板化 + 表现力参数化。

## 二、业务目标与成功指标

### 业务目标

从「生成一次内容」到「运营一类内容」。平台解决的不仅是单次写作效率问题，而是建立起一套**持续运营历史内容品类的工艺标准和基础设施**。一旦冷启动配置完成（系列品牌定义、知识库建设、文风包逆向工程），新增一个历史知识点从入库到全形态输出的边际成本趋近于零。

### 关键成功指标

| 指标 | 定义 | 目标值 |
| --- | --- | --- |
| 知识节点到全形态输出时长 | 从新建一个历史知识节点（含选材字段标注）到完成结构化文本、SSML 音频脚本、动画分镜标签输出的端到端时间 | ≤5 分钟 |
| 同主题多版本派生效率 | 同一知识库 + 切换文风包，一键生成大众版/学术版/公众号版所需的人工微调时间 | ≤10% 原文需人工调整 |
| 系列作品风格一致性通过率 | 新生成章节通过系列一致性校验（主旋律复现、文风包偏离度、禁止模板使用）的比例 | ≥95% |
| 对抗评审通过率 | 生成稿在轻度对抗评审（史观审计 + 读者代言人）中首次通过率 | ≥80% |
| 人工干预占比 | 编辑手动 override（选材 pin/boost/exclude、模板替换、张力手动微调）占全部决策动作的比例 | 持续下降，稳态 ≤15% |

## 三、功能需求

### 3.1 冷启动配置层

冷启动是平台的一次性重投入阶段，定义好所有规则和资产后，全自动生产才可启动。冷启动配置层包含以下五大模块。

#### 3.1.1 系列品牌定义（Series Profile）

Series Profile 是系列作品的「品牌 DNA」，所有单书配置继承并受其约束。包含：共享史观引用（可被子书局部 override）、共享主旋律声明及变奏策略（如「一切宏大叙事的崩塌，都始于技术治理的缺位」）、共享文风包锁定及禁止偏离项、模板角色偏好（主力模板/辅助模板/禁用模板）、冲击力政策（反常识数据要求、最大耸动度、事实完整性硬约束）、读者基调、品牌标识（跨模态签名：封面意象、音频固定开场白）。

#### 3.1.2 史观参数包配置（Historiography Profile）

史观包负责控制「说什么、站在哪边、褒谁贬谁」，与文风包（管「怎么说」）解耦。包含五项结构化参数：

**(1) 核心立场向量（Stance Vector）**：可量化、可审计的数值向量。包含 `individual_agency`（个人作用权重）、`structural_determinism`（结构决定论强度）、`moral_judgment`（道德评判倾向）、`great_man_theory`（英雄史观倾向）、`popular_agency`（群众能动性），取值区间 [-1, 1]。例如结构唯物主义史观配置为 individual_agency=-0.3, structural_determinism=0.8, moral_judgment=-0.7, great_man_theory=-0.8, popular_agency=0.6。

**(2) 情绪基调（Emotional Tone）**：全局情绪底色（如 sober_detached），对权力方的态度（如 skeptical），对弱势方的态度（如 empathetic_but_not_sentimental）。

**(3) 价值观关键词**：approved 词表（如「制度困境」「结构性矛盾」「技术治理」「路径依赖」），discouraged 词表（如「昏庸」「奸佞」「圣明」「天意」），forbidden 词表（如「种族优劣」）。这些词表在渲染时硬约束 LLM 输出。

**(4) 模板偏好（Template Bias）**：对 10 个模板的倾向性浮动分值，如 TPL_01（小事撬动大局）+0.2，TPL_03（制度杀人）+0.2，TPL_02（命运抉择）-0.3——直接影响模板选择器 Layer 3 的语境修正。

**(5) 情绪注入规则（Emotion Injection）**：定义不同叙事场景的情绪处理方式，如 toward_systemic_tragedy: "quiet_sorrow"，toward_individual_struggle: "restrained_respect"，toward_irony_of_history: "subtle_irony_no_laughter"。

#### 3.1.3 读者画像配置

读者画像不是营销意义上的用户画像，而是**知识边界 + 情感原型**的组合：

- **认知基线**：分 solid/fuzzy/unknown 三级标注读者对各历史概念的认知状态
- **认知桥梁域**：读者偏好的类比来源域，如 corporate_structure/project_management/office_politics，同时标注反感项如 excessive_dates
- **情感原型**：核心情感身份（如 ambitious_but_trapped_professional），共鸣标签（如 systemic_frustration/career_ceiling），排斥标签（如 peasant_uprising_glorification）
- **阻抗地图**：读者可能产生抵触的表述方式
- **深层需求**：阅读动机（如「寻找对当下困境的解释框架」）
- **语言亲和度**：对口语化/学术化/网络流行语的接受阈值

#### 3.1.4 文风包管理——五层形式化维度

文风包（Style Pack）将优秀历史作家的隐性叙事风格拆解为五层可参数化约束：

```
StylePack
 ├─ L0. Meta：适用体裁、目标受众、禁止项
 ├─ L1. Persona：叙述者角色及语调定位
 ├─ L2. Lexical Pool：开场语池、连接词池、类比触发词、禁词表
 ├─ L3. Syntactic Bias：平均句长、问句比例、被动语态、段落节奏
 ├─ L4. Rhetorical Ops：比喻密度、设问策略、史料展示方式、反讽开关
 └─ L5. Layout/Pacing：框类型偏好、张力弧线默认映射
```

以黄仁宇式文风包为例：Persona 为 "detached_observer_with_structural_vision"，tone 为 calm_analytical_with_subtle_irony；Lexical Pool 开场语为「从表面上看」「若从制度层面审视」等，禁词表包含「令人震惊」「不可思议」「毋庸置疑」；Syntactic Bias 偏好中长句、高从句密度、允许被动语态；Rhetorical Ops 要求 mild_irony、macro_micro_link（必做小事到大结构的跳跃）、一手史料引用稀疏但精确。

#### 3.1.5 文风包逆向工程工具

提供从标杆作品中系统提取文风包的操作工具：

1. **样本准备**：选取目标作者 3-5 万字纯文本正样本 + 同期同题材其他作者负样本（差分提取个性特征），排除对话体、访谈、序跋
2. **逐层提取**：Layer 2 用 TF-IDF 差分（正样本-负样本）+ 人工标注分类；Layer 3 用脚本跑可量化特征（平均句长、问句比例、破折号频率、被动语态比例、段落行数）→ 写入约束而非复制分布；Layer 4 随机抽 100-150 个说理单元人工标注类比密度、源域偏好、设问模式
3. **校验与迭代**：盲评测试（生成 3 段 + 混入 2 段原作，请 5-8 位读者辨识，命中率 >60% 可用 v1，>75% 优质）+ 定量辅助（JS 散度、句长分布是否落入原作 95% CI）。迭代时只改 YAML/池子，不改模板逻辑、不碰模型

### 3.2 知识库层

#### 3.2.1 历史知识节点结构

知识库以**事件 + 人物 + 制度 + 观念**四元组为基本实体。每个知识节点除基础字段（node_id、node_type、时间、别名、叙事钩子、结构洞察、常见误区列表、类比池）外，核心是**选材加权字段**，直接驱动选材引擎评分：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| significance | 向量(political/economic/cultural/personal_agency/symbolic_power) | 各维度重要性 0-1 分，用于与史观包 stance_vector 做点积匹配 |
| dramatic_potential | 对象(has_dramatic_irony/has_moral_dilemma/has_visible_consequence/score) | 戏剧潜力综合评分 0-1 |
| source_quality | 对象(primary_sources/reliability/contemporary) | 一手史料数量与可靠性 |
| narrative_fit_tags | 字符串数组 | 匹配的叙事意图，如 INTENT_TRAGEDY/INTENT_MICRO/INTENT_REVISION |
| reader_resonance | 映射(persona_id→0-1) | 各读者画像与该节点的情感共鸣度 |
| impact_potential | 对象(counter_intuitive_score/precision_data/emotional_valence/memorable_phrase_seed) | 冲击力数据资产，含反常识评分 0-1、精确数据+对比语境+史料出处、情绪效价、可记忆短语种子 |

#### 3.2.2 知识点依赖图

构建三类依赖关系：**时间线依赖**（事件按时间升序，除非明确标记 flashback）、**因果关系依赖**（事件 A 是事件 B 的前提）、**前置知识依赖**（概念 A 必须在概念 B 之前介绍，如「先讲明代内阁制度，再讲票拟/批红流程」）。规则引擎在编排时自动校验依赖图，未覆盖前置知识则不生成后续内容。

#### 3.2.3 冲击力数据资产

在知识节点入库时由领域专家标注，包含反常识评分 counter_intuitive_score（0-1）、精确数据 precision_data（数字+对比语境+史料出处）、情绪效价 emotional_valence（shock_and_despair/awe/ironic_amusement）、可记忆短语种子 memorable_phrase_seed。示例：「国库仅剩白银 2300 两，尚不足皇室一日脂膏」——《明实录·崇祯朝》。

### 3.3 选材引擎

选材引擎是历史通俗作品区别于教材/科普的**核心差异模块**——教材是「大纲驱动，全集固定」，历史通俗是「目标驱动，主动挑戏」。

#### 3.3.1 叙事意图定义

六种叙事意图：INTENT_EPIC（宏大叙事/通史，偏好标志性转折事件与制度突变点），INTENT_MICRO（微观史/社会生活，偏好普通人日记与地方档案），INTENT_TRAGEDY（制度悲剧/改革失败，偏好改革者困境与制度反弹），INTENT_REVISION（翻案/修正史，偏好被误读人物与冷门一手史料），INTENT_PERSONAL（人物传记/心理史，偏好关键抉择点与书信），INTENT_IDEATIONAL（观念史/思想史，偏好关键文本与概念演变节点）。

#### 3.3.2 选材评分公式

```
S = α·IntentFit + β·DramaticPotential + γ·SourceQuality + δ·ReaderResonance + ε·HistoriographyBias
```

| 项 | 含义 | 计算方式 | 典型权重 |
| --- | --- | --- | --- |
| IntentFit | 叙事意图匹配度 | 节点 narrative_fit_tags 含当前 INTENT→1，否则降权 | α=0.35 |
| DramaticPotential | 戏剧性潜质 | 直接读取 dramatic_potential.score | β=0.25 |
| SourceQuality | 史料可靠性 | (primary_sources×reliability)归一化 | γ=0.15 |
| ReaderResonance | 读者共鸣度 | RP.typical_reader_resonance[persona_id] | δ=0.15 |
| HistoriographyBias | 史观亲和度 | HP.stance_vector 与节点 significance 向量的点积 | ε=0.10 |

权重可随作品类型微调：通俗版调高 δ（读者共鸣），学术版调高 γ（史料可靠性），偏好故事的作者调高 β，重考据的作者调高 γ。这就是「把选材品味参数化」。

#### 3.3.3 选材约束

五项硬约束防止「分高但叙事不合理」：覆盖均衡（同一章至少一个 #micro_event 和一个 #structural_explanation）、时间顺序（除非明确 flashback，节点按时间升序）、多视角（TRAGEDY/REVISION 章节须含对立视角节点）、戏剧密度上限（连续>2个 dramatic_potential>0.8 节点需插入 ≤0.4 的缓和节点）、来源最低要求（每个选定事件须有 ≥1 一手史料或高可靠性二手史料）。

#### 3.3.4 作者干预接口

选材并非剥夺选择权，而是将「品味」显式化：手工调权 (boost)、锁定必选 (pinned)、排除节点 (excluded)、微调五项权重系数。所有干预操作记录原因，形成可复用的「选材品味档案」。

### 3.4 编排引擎

#### 3.4.1 10 种叙事模板（TPL-01 ~ TPL-10）

| ID | 名称 | 核心逻辑 | 结构序列 |
| --- | --- | --- | --- |
| TPL-01 | 小事撬动大局 | 微观事件→宏观结构 | 情境→事件→人物→结构→反思 |
| TPL-02 | 命运抉择时刻 | 压力→抉择→不可逆后果 | 情境→人物→事件→后果→反思(含反事实) |
| TPL-03 | 制度杀人 | 好人+好意→坏制度→必然毁灭 | 人物→情境→事件→结构→后果→反思 |
| TPL-04 | 文明碰撞 | 两种逻辑体系不对称相遇 | 情境A→情境B→事件→分析→后果→反思 |
| TPL-05 | 技术改变社会 | 技术突破→社会结构重组 | 情境→事件→分析→结构→反思 |
| TPL-06 | 观念诞生记 | 旧观念危机→新思想→社会接受/排斥 | 情境→人物→事件→分析→后果→反思 |
| TPL-07 | 被遗忘的多数 | 宏大叙事之外普通人的生存逻辑 | 情境→事件→人物→分析→反思 |
| TPL-08 | 历史反转 | 常识认知→新证据→认知反转 | 情境(常识)→事件(新史料)→分析→结构→反思 |
| TPL-09 | 长时段缓慢变化 | 几乎不变→缓慢积累→突然显现 | 情境(稳态)→分析(缓慢指标)→事件(临界点)→结构→反思 |
| TPL-10 | 复调历史 | 同一事件不同立场各自合理 | 情境→人物A视角→人物B视角→分析→反思 |

每个模板附带 required_tags、forbidden_tags、transition_rule 和 style_injection 指令。

#### 3.4.2 模板选择器——三层漏斗模型

**Layer 1 硬性过滤**：每个模板声明 precondition（required_labels / forbidden_labels / min_scale / preferred_node_type），不满足直接淘汰。将 10 个模板筛至 2-3 个候选。

**Layer 2 加权评分**：FinalScore = 0.4×LabelOverlap + 0.25×StructuralFit + 0.2×NarrativePotential + 0.1×SourceRichness + 0.05×HistoriographyMatch。标签重合度用 Jaccard 相似系数计算，结构契合度考察节点在知识图谱中的位置（如 TPL-01 偏好属于更大历史进程的节点 +0.3，TPL-04 偏好存在可比对象的节点 +0.5），叙事潜力考察 dramatic_irony/moral_dilemma 标签。

**Layer 3 语境修正**：章节位置修正（开篇偏好 TPL-01/TPL-04 +0.1，转折偏好 TPL-02/TPL-08 +0.1，结尾偏好 TPL-09/TPL-10 +0.1），前后文一致性惩罚（连续两节相同模板 -0.15），史观参数修正（HP 中 template_bias 直接加减）。

输出完整的 decision_trace，包括硬性过滤淘汰原因、五维评分明细、语境修正记录。

#### 3.4.3 COG 编排语法

COG（Chapter Orchestration Grammar）是章节级「导演分镜脚本」语言，定义六种章节角色：

| 角色 | 定义 | 常配模板 |
| --- | --- | --- |
| anchor_event | 锚定事件，章节叙事起点 | TPL-01(3), TPL-02(3) |
| deep_dive | 深入制度/心理内部 | TPL-03(3), TPL-05(3), TPL-06(3) |
| counterpoint | 提供对立/修正视角 | TPL-08(3), TPL-10(3), TPL-07(3) |
| macro_frame | 提供长时段/结构框架 | TPL-04(3), TPL-09(3), TPL-05(3) |
| synthesis | 综合前文，升华主题 | TPL-06(3), TPL-07(1) |
| bridge | 承上启下 | TPL-07(3), TPL-01(2) |

四种经典编排模式：Pattern A「微观→修正→宏观」[anchor_event, counterpoint, macro_frame]，Pattern B「抉择→毁灭→反思」[anchor_event, deep_dive, synthesis]，Pattern C「碰撞→变革→复调」[macro_frame, deep_dive, counterpoint]，Pattern D「沉默→结构→发声」[counterpoint, deep_dive, synthesis]。

过渡类型：cognitive_contrast（认知对比）、temporal_expansion（时间膨胀）、psychological_deepening（心理深化）、structural_leap（结构跃升），每种过渡有其 marker 文本模板和张力变化方向。

#### 3.4.4 角色亲和度矩阵（10×6）

| 模板ID | anchor_event | deep_dive | counterpoint | macro_frame | synthesis | bridge |
| --- | --- | --- | --- | --- | --- | --- |
| TPL-01 | **3** | 2 | 1 | 2 | 0 | 2 |
| TPL-02 | **3** | 2 | 0 | 0 | 1 | 1 |
| TPL-03 | 2 | **3** | 1 | 1 | 0 | 1 |
| TPL-04 | 2 | 2 | 2 | **3** | 1 | 1 |
| TPL-05 | 1 | **3** | 1 | **3** | 2 | 1 |

3=天生契合首选，2=可用次选，1=勉强可用需人工微调，0=违和禁止自动选用。加粗为主角色。

#### 3.4.5 编排校验引擎

渲染前五项检查：角色唯一性（Section 角色不重复）、张力单调性（tension_weight 趋势合理非严格递增）、过渡合法性（如 temporal_expansion 要求 to_tpl.scale > from_tpl.scale）、节奏呼吸（禁止连续两个高密度模板 + 章节中间必须有一次低密度 + 结尾必须是中低密度）、史观一致性（所有 Section 文风包与章节史观兼容）。

---

### 3.5 心理动力学编排层（PDL）

PDL 将剧本/剧作手法翻译为模板系统的可执行约束，实现「全程无尿点」的工程化。

#### 3.5.1 悬念构建——认知落差槽

利用「后见之明」制造戏剧性反讽：读者知道历史结局，人物不知道。每个 anchor_event 模板实例必须包含 dramatic_irony_marker 槽位，通常在单元结尾。示例：「此时，申时行并不知道，这一封奏折将在十七年后，成为萨尔浒之战溃败的注脚。」

#### 3.5.2 张力阶梯 + 呼吸段

每个 Section 标注 tension_level（0-1），pressure_source 必须与前一节构成递进或转化关系。禁止 tension_level 连续下降。动态呼吸规则：高密度单元后必须跟中或低密度单元；连续三个中密度后必须插入低密度单元。密度分类：high=[TPL-03, TPL-06, TPL-09]，medium=[TPL-01, TPL-04, TPL-05]，low=[TPL-07, TPL-10]。

#### 3.5.3 高潮设计

每个 Chapter 必须有且仅有一个 is_chapter_climax: true 的单元。高潮不是快节奏，而是慢、沉、重的结构跃升时刻。位置在结构分析单元（TPL-01 的 structure_unit 或 TPL-09 的全景分析），节奏标记 slow_unfolding，情绪承载 tragic_inevitability 或 paradigm_shift。前后必须有明显节奏变化。

#### 3.5.4 六大钩子槽位

开篇悬念钩（章首，指向已知结局）、认知落差钩（情境单元末）、矛盾钩（矛盾升级点）、信息差钩（分析单元中）、高潮钩（结构跃升单元）、结尾钩（章末，指向下一章伏笔）。

#### 3.5.5 钩子投放规则

每章标配开篇悬念钩+结尾钩。中间至少一个信息差钩或矛盾钩。结尾钩必须与史观包情绪基调一致。除最后一章外，所有章节必须有结尾钩。

---

### 3.6 冲击力注入层

#### 3.6.1 评分模型

冲击力 = 反常识密度 × 数据精确性 × 情绪唤醒度。评分直接读取知识节点的 impact_potential.counter_intuitive_score。它不是标题党，而是在叙事「穴位」上释放被平淡叙述掩盖的真实震撼。

#### 3.6.2 四类投放位置

开篇 Hook（若为 dramatic_irony 场景，优先使用高 counter_intuitive_score 数据）、矛盾升级点（tension_level 上升阶段，插入 precision_data）、高潮前静默（Climax 单元前，用极简数据打断抒情，制造窒息感）、结尾 Hook（用 precision_data 指向当下，形成回响）。

#### 3.6.3 冲击力硬约束

require_primary_source: true（数据必须源自可靠史料），forbid_superlative_distortion: true（禁止「史上最……」式夸张），severity: error。违反即阻断生成。

---

### 3.7 主旋律记忆层

#### 3.7.1 主旋律定义与变奏

主旋律 = 贯穿全篇、可被反复感知、最终沉淀为认知或警句的核心命题。借鉴瓦格纳歌剧的 Leitmotif 手法，每章三节点变奏：开篇陈述式暗线 → 矛盾激化处反问式 → 高潮论断式强奏 → 结尾警句式变奏收束。示例：陈述式「这又是一个试图用道德填补技术真空的故事」→ 论述式「这就是结构性困境的本质：道德是锦上添花，技术是雪中送炭」→ 警句式「历史从不重复，但缺乏技术底座的宏大叙事，总会以相似的方式塌方。」

#### 3.7.2 当代映射规则

反思单元强制注入 contemporary_resonance 槽位，逻辑 link_to_present，historiography_link: "all_history_is_contemporary_history"。示例：「当我们今天抱怨『流程繁琐、审批低效』时，不妨想想崇祯的谕旨——那是同一个幽灵，在两个时空的回响。」

#### 3.7.3 防空洞检测

主旋律复现必须满足：落到一个具体的知识节点（有史料/数据支撑）或落到读者画像中标注的当下具体问题（有 relatable 场景），否则标记为「空洞」。

---

### 3.8 对抗评审层

#### 3.8.1 五个对抗 Agent

| Agent | 攻击目标 | 典型攻击角度 |
| --- | --- | --- |
| 史观审计员 | 史观一致性 | 检测 forbidden_keywords 使用、individual_agency 权重超标、情绪基调漂移 |
| 读者代言人 | 连接点有效性 | 类比失效、情感错位、知识门槛过高 |
| 叙事评论家 | 心理动力学 | 悬念造假、张力虚假、高潮疲软 |
| 真实性守护者 | 冲击力与主旋律 | 数据争议、标题党化、主旋律空洞 |
| 视角挑战者 | 选材偏见 | 视角单一（全章只见皇帝大臣）、翻案过度忽视对立史料 |

#### 3.8.2 评审输出格式

结构化、可审计：passed 状态、reviewer 身份、issues 数组（每项含 dimension/severity/location/issue/suggestion/auto_fixable）、overall_comment。

#### 3.8.3 对抗强度等级

轻度（草稿自检，仅规则对抗，标记警告允许继续）、中度（内部打磨，规则对抗+史观审计员+读者代言人 LLM 对抗，返回修改建议需人工确认）、重度（出版前终审，全部五个 Agent，不通过阻断渲染）。

#### 3.8.4 对抗 Agent 自身审美约束

对抗 Agent 的 Prompt/规则中必须注入：史观包（不能用自己的史观乱批）、读者画像（知道谁是目标读者）、审美标准（知道「好作品」的维度定义）。对抗 Agent 不是自由的批评家，而是「戴着镣铐的考官」。

---

### 3.9 受控生成层

#### 3.9.1 LLM 填槽模式

本平台最核心的生成哲学：**LLM 不是在创作，而是在填槽**。每个模板单元被拆解为明确的 fill_slots JSON Schema，LLM 只能在指定槽位内输出受约束文本，不能修改模板结构、增删单元、跨过模板的角色和标签约束。

#### 3.9.2 文风包注入规则

渲染时文风包按五层顺序逐层注入 Prompt/填槽指令：Meta→系统提示词；Persona→角色设定；Lexical Pool→填槽时随机选连接词+输出后硬过滤禁词；Syntactic Bias→Prompt 约束+输出后统计校验；Rhetorical Ops→Prompt 约束；Layout/Pacing→模板默认+COG 覆盖。

#### 3.9.3 情绪弧线自动标注

每个 Section 在生成时自动附加情绪弧线标签（narrative_hook/cognitive_buildup/cognitive_conflict/aha_moment/reflective_close/dramatic_irony/structural_reveal/tragic_climax），用于后续 SSML 音频脚本和动画分镜。

#### 3.9.4 读者连接点自动挖掘

知识连接点：知识点属于读者画像中 unknown/fuzzy 领域时，自动从读者偏好类比源域搜索类比池，填入 cognitive_bridge 槽位。情感连接点：提取节点 emotional_tone 与读者 resonates_with 标签匹配，匹配成功则生成 emotional_bridge 文本。示例：「你可以把明代内阁想象成一个没有最终签字权的『总经办』……」

---

### 3.10 多模态输出层

- **结构化历史文本**：主输出为 Markdown 书稿（含知识卡片、类比框、时间轴、史料引用块），派生输出为一键文风包切换生成大众版/学术版/公众号版
- **SSML 音频脚本**：基于情绪弧线标签自动生成语音标记，narrative_hook→略快步速+疑问语调，dramatic_irony→放慢+凝重，structural_reveal→显著放慢+加重音+≥800ms 停顿，aha_moment→emphasis="strong"+重复一次
- **动画分镜标签**：基于模板自动标注需求（TPL-01 结构跃升→institutional_structure 图示，TPL-09 长时段→timeline_with_data_curve，因果链→causal_arrow_propagation 动画），含时间戳+动画类型+图形元素+情绪弧线同步标记
- **交互知识卡片**：单个节点+连接点+冲击力数据打包为 JSON，支持知识卡片/FAQ 问答对/分步引导式卡片

---

### 3.11 品牌管理

#### 3.11.1 系列品牌圣经（Brand Bible）

Series Profile 即 Brand Bible，含品牌定位、核心价值观、嗓音标识、记忆锚点、叙事性格、冲击力政策、视觉/听觉签名、系列一致性承诺。有版本号，支持迭代，子书继承最新版或锁定特定版本。

#### 3.11.2 多系列 IP 隔离与复用

隔离：每个 Series 拥有独立配置空间。复用：文风包、读者画像、通用知识节点可跨系列共享。冲突检测：同机构运营多系列时，系统自动计算风格相似度（JS 散度<0.2 触发品牌稀释警告）。

#### 3.11.3 系列一致性校验

渲染前校验：主旋律是否在本章出现并变奏、文风包偏离度是否在 ±0.05 内、是否误用系列禁用模板、章末是否有当代映射、冲击力是否遵守系列政策。

## 四、非功能需求

### 性能

相同冷启动配置下，新增一个完整标注的知识节点到首版结构化文本输出 ≤5 分钟。多版本派生（换文风包）<1 分钟。支持并行处理：不同章节在无依赖冲突时可并行编排/渲染。

### 可扩展性

新体裁（企业白皮书/金融投教/医疗科普）通过新增模板库+领域知识库即可接入，不改核心引擎。新文风包独立注册入库。新叙事模板仅需填写 precondition/preferred_labels/role_affinity 三个配置。新对抗 Agent 角色独立注册。

### 可审计性

所有决策链路可回溯：选材引擎每节点五项分项明细+编辑 override 记录；模板选择器完整 decision_trace；编排引擎角色指派理由+过渡选择理由+张力曲线数据；对抗评审每个 issue 的位置/维度/严重度/修改建议；受控生成每次 LLM 调用的 Prompt 模板+填槽指令+输出快照。

### 多模型兼容

LLM 可替换，不绑定特定模型。填槽 Prompt 使用标准化接口。文风包、模板、规则引擎均独立于 LLM，换模型不影响已沉淀创作资产。

### 安全性

历史内容合规审查（可选合规 Agent）、版权保护（史料引用自动附加出处、禁止整段复刻现代作品原文）、数据安全（文风包逆向提取语言特征不存储原作全文）。

## 六、实施路线图

### Phase 1：MVP 核心验证（3-4 个月）

**目标**：以 K12 教育场景中已验证的核心方法论为基线，落地历史通俗作品的最小可行闭环。

- 完成 10 种叙事模板（TPL-01~TPL-10）的完整 Schema 定义及模板-角色亲和度矩阵

- 实现单个文风包（黄仁宇式 cp_history_huang_renyu_v1）的完整五层定义及渲染注入
- 构建最小知识库（晚明历史 30-50 个知识节点，含选材加权字段和冲击力数据）
- 实现模板选择器三层漏斗（硬性过滤 + 加权评分 + 语境修正）
- 实现 LLM 填槽模式的标准化 Prompt 接口
- **交付物**：用崇祯最后一道谕旨、申时行奏折事件等知识点，生成 2-3 个完整章节（含结构化文本输出）

- 实现史观参数包（五参数 stance_vector + 情绪基调 + 价值观关键词 + 模板 bias + 情绪注入规则）的完整配置及渲染注入
- 实现读者画像（六级参数：认知基线/认知桥梁域/情感原型/阻抗地图/深层需求/语言亲和度）及连接点自动挖掘引擎
- 实现选材引擎完整管线（六种叙事意图 + 五项加权公式 + 五项选材约束 + 作者干预接口）

- 实现冲击力注入层（评分模型 + 四类投放位置 + 硬约束校验）
- 实现主旋律记忆层（变奏策略 + 当代映射规则 + 防空洞检测）
- 完成黄仁宇式和《明朝那些事儿》式两种文风包的逆向工程和注册
- **交付物**：可生成一部完整历史通俗作品的全部章节草稿（约 8-12 万字）

### Phase 3：质量保障与品牌运营（2-3 个月）

- 实现五维对抗评审系统（五个 Agent 的 Prompt/规则模板 + 三级强度开关 + 结构化输出 + 人类编辑 override 接口）
- 实现 Series Profile 全功能（品牌圣经管理 + 子书继承/override + 版本控制）

- 实现多模态输出：SSML 音频脚本自动生成、动画分镜标签自动生成、交互知识卡片输出
- 完成文风包逆向工程工具的脚本化（样本准备→TF-IDF 差分→特征统计→一键生成 YAML 草稿）
- **交付物**：经对抗评审打磨后的终稿 + 配套音频脚本 + 动画分镜标注，可直接交付出版社或内容制作团队

- 多系列 IP 管理：同时运营多个系列（如「结构中国」系列 +「微观晚明」系列），隔离配置空间，复用共享资产，自动检测品牌稀释风险
- 第三方接入：开放 Series Profile 模板、文风包注册接口、知识库 API，允许出版社/内容机构上传自有史观包和读者画像

- **交付物**：面向出版社和内容机构的 SaaS 平台

## 七、风险与约束

### 7.1 历史准确性与叙事表现力的平衡

**风险**：在追求「全程无尿点」的心理动力学效果时，可能滑向过度戏剧化，损害历史准确性。

**对策**：三层防线。第一层——冲击力硬约束（require_primary_source + forbid_superlative_distortion），所有精确数据必须标注史料出处；第二层——真实性守护者对抗 Agent，专门检测数据争议和标题党倾向；第三层——人工编辑对重度对抗评审的终审权，涉及敏感历史人物/事件的段落必须人工 sign-off。

### 7.2 偏见注入风险

**风险**：史观参数包是显式的立场配置——这既是优势也是风险。「正确」的史观由谁定义？如果结构唯物主义史观被设定为「权威默认」，是否压制了其他视角？

**对策**：多史观并存（系统不预设「正确」史观，允许多个史观包并行存在）；显式标注（每部作品前言中自动附带史观包摘要，告知读者立场）；视角挑战者 Agent 专门检测单视角偏见，对任何史观包生成的文本都进行多视角平衡检查。

### 7.3 风格趋同风险

**风险**：过度依赖 10 种叙事模板 + 固定文风包，可能导致系列作品内部以及不同系列之间出现同质化。

**对策**：受控变异策略——每部书需在选材范围、叙事意图、主旋律变奏深度、读者微调维度上做出差异化；系列间风格相似度自动检测（JS 散度 <0.2 触发警告）；文风包的 prohibited 词表 + 模板的 forbidden_tags 保证不同系列有明确边界。

### 7.4 LLM 依赖风险

**风险**：模型更新可能改变填槽行为，导致风格漂移。

**对策**：多模型兼容设计——文风包、模板、规则引擎独立于 LLM；每次模型切换后，用同一批填槽指令跑回归测试（对比新旧模型输出的风格指标：句长分布/词汇 JS 散度/情绪词比例），偏离超过阈值则微调 Prompt 模板。

### 7.5 版权与合规

**风险**：史料引用边界、历史人物评价边界（如对近现代人物的评价可能触发审查）、文风包逆向工程的法律定性。

**对策**：所有史料引用自动附加出处标注；知识节点中涉及近现代人物/事件的内容增加合规标记，在对抗评审层加载合规 Agent；文风包逆向工程仅提取可观测语言特征（词频分布、句式统计、修辞模式），不存储或复现原作大段文本，降低版权风险。
